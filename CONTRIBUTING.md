# Участие в разработке

Начните с [README](README.md), [текущей готовности](docs/STATUS.md), [плана](docs/DEVELOPMENT_PLAN.md), применимых ADR и [правил для агентов](AGENTS.md). Требования первого выпуска, клиентская матрица и исключения определяются планом; новую функцию не включайте скрыто в согласованный объём.

## Рабочий процесс

1. Выберите Issue из [карты задач](docs/ISSUE_ROADMAP.md), прочитайте критерии/родителя/зависимости и обозначьте проверяемый результат. Текущий приоритет аудита задают [ADR 0008](docs/adr/0008-audit-development-sequence.md) и [реестр](docs/audit/2026-10-11-follow-up.md).
2. Проверьте изменения владельца и создайте отдельную ветку. Для независимого design/fixture инкремента объясните, какая часть разрешена до полной приёмки этапа.
3. Обновляйте фактический рабочий статус по [правилам Project](docs/PROJECT.md). При недоступном API оставьте статус, зависимости и родителей в Issue; не заявляйте обновление доски.
4. Представьте PR с Issue, ID находки аудита, поведением до/после, проверками и ограничениями. Для частичного выполнения — `Refs #N`, для полного — `Closes #N`. Приёмка GUI/DSM не закрывается от успешного CI.
5. После полной приёмки синхронизируйте эпик, зависимые задачи и статус. Не сливайте PR и не выпускайте tag/release без соответствующего задания.

Новые межэтапные задачи включаются в существующие Milestones/эпики. Не создавайте параллельный backlog аудита и не дублируйте критерии уже существующей задачи.

## Среда и код

Точный SDK — в `global.json`, central package versions/lock-файлы — в репозитории. [README](README.md#сборка-и-демонстрация) содержит команды, [M1](docs/m1/README.md) — GUI, native probe и self-contained публикацию. Locked restore обязателен; lock-файлы меняются при намеренном обновлении зависимостей.

Соблюдайте границы Domain/Application/Infrastructure/Desktop и MVVM. Пишите развёрнутые условия/методы, один оператор на строку; UI тексты — в Desktop. Форматирование, исправления поведения, архитектурные переносы и обновление версий оформляйте отдельными проверяемыми PR. Настройка formatter/Recommended analyzers/Dependabot/coverage ведётся в #98 и пока не объявляется выполненной.

## Проверки

Для изменений кода: locked restore, Release build, релевантные unit/contract/headless проверки и применимая Windows/Linux матрица CI. Для исправления поведения добавьте регрессию, которая демонстрирует исходную ошибку. Не пишите зеркальные unit-тесты для низкорисковой правки документации.

Для мутаций проверяйте ownership/identity/conflicts, timeout и caller cancellation до/после отправки, lost response и resume. Дедлайн чтения и неизвестный результат записи различаются явным типом. Observe предшествует повтору; 4xx не разрешает повтор без доказательства отсутствия изменения.

Для изменения профиля проверяйте schema/hash/source, pins ↔ clients/probes/CI, параметры ролей и semantic YAML. Свежие секреты и реальные identities пользователя в fixtures не включаются. При рефакторинге HA сохраняйте безопасные auth/session revoke, contract/runtime и flow проверки.

Результат запуска указывает commit/profile/версии, среду, сценарии и ограничения. Fixtures, Docker, CI native GUI, обычный клиентский рабочий стол и настоящая DSM имеют разные доказательства. Незапущенная проверка остаётся непроверенной. Пробы на NAS выполняются только в авторизованном задании и согласованной среде.

## Документация и секреты

[STATUS](docs/STATUS.md) хранит текущую готовность; README — назначение/запуск/ссылки, план — требования и зависимости, протоколы — исторические доказательства, CHANGELOG — фактически внесённые изменения. Не копируйте текущие числа тестов в прозу; берите их из отчётов. Исторические числа в датированных доказательствах не заменяйте новыми.

При устранении находки обновите Issue и соответствующую строку реестра аудита с PR/commit и доказательством. Обновление плана не считается исправлением ошибки. Изменение готовности требует STATUS; изменение требований/этапов — плана и ADR.

Проверяйте Markdown/относительные ссылки, UTF-8/LF и diff. В CHANGELOG один раздел каждого типа внутри версии. UI/документы — по-русски, идентификаторы кода — по-английски.

Credentials/API tokens/OTP/private keys/secret URL не публикуются в коде, логах, снимках, протоколах или PR. Для примеров используйте безопасные синтетические данные. [ADR 0002](docs/adr/0002-journal-and-secrets.md) и AGENTS определяют журнал, unknown outcome, TLS и сохранение данных.
