# Правила написания кода

Документ фиксирует единый стиль кодовой базы hh-homelab-wizard. Цель — человекочитаемый код: тот, кто читает метод впервые, понимает его без отладчика и без разбора многострочных выражений.

Правила дополняют [AGENTS](../AGENTS.md) и [CONTRIBUTING](../CONTRIBUTING.md), не заменяя их. Архитектурные ограничения (слои, порты, журнал, секреты) остаются в AGENTS и ADR; здесь — только то, как код выглядит и читается.

Механическое закрепление правил форматтера и анализаторов выполняется в задаче #98; до её завершения соответствие обеспечивается ревью.

## 1. Строки и операторы

- Один оператор на строку. `a(); b();` в одной строке запрещено, включая поля и catch-фильтры.
- Одно объявление на строку: `private bool busy, closing;` запрещено, каждое поле объявляется отдельно.
- Пустая строка между членами типа (полями, свойствами, методами). Склеенные блоки без разделителей запрещены.
- Логические шаги внутри метода отделяются пустой строкой: проверка аргументов, чтение состояния, запись, наблюдение результата.
- Отступ — 4 пробела, перевод строки LF, кодировка UTF-8.

## 2. Условия

Условие читается как фраза. Если операндов больше двух, условие раскладывается.

- **1–2 операнда** — допустимо прямо в `if`/`while`.
- **3 и более операндов** — каждый осмысленный фрагмент получает имя:

```csharp
var portUnexpected = Int(baseline, "server_port") != 8123;
var tlsConfigured = baseline["ssl_certificate"] is not null || baseline["ssl_key"] is not null;
if (portUnexpected || tlsConfigured)
    throw new MediaContractException("ha.http.baseline-conflict");
```

- **Стражи с зависимостью по короткому замыканию** (проверка null/длины защищает обращение к элементу) раскладываются в последовательные `if` с тем же исключением, в исходном порядке:

```csharp
if (found.Length != 1)
    throw new MediaContractException("ha.entity.conflict");
var current = found[0];
```

- **Порядок вычисления не меняется.** `&&`/`||` с побочными эффектами (`seen.Add(...)`, обращения к API, `out var`) выносятся в отдельные проверки строго в исходной последовательности. Первым всегда идёт то, что делает последующие операнды безопасными.
- **Цепочки с pattern-переменными** (`state["stable"] is JsonObject stable && ...`) допустимо оставлять вертикальным списком: pattern-переменная сама документирует шаг. После такой проверки компилятор должен видеть сужение nullable без `!`.
- Имена булевых переменных — утверждения: `entryNotLinked`, `trialInactive`, `countsOnly`. Читается: `if (identityChanged || entityIdUnexpected || targetTaken)`.

## 3. Методы

- Метод отвечает на один вопрос и помещается на экран (ориентир — до 60 строк). Больше — выделяются этапы в приватные методы с глаголом в имени.
- Порядок внутри метода: проверка аргументов → чтение состояния → решение → запись → наблюдение. Проверки аргументов идут первыми, без вложенности.
- Предикаты, повторяющиеся или занимающие больше двух строк, выносятся в локальные функции или приватные статические методы (`HasLocation`, `HasServerIdentifier`).
- Публичные контракты с безопасностными последствиями снабжаются XML-doc: что метод доказывает, а что нет («an open endpoint is not proof of completed startup»).

## 4. Имена

- Идентификаторы — на английском; UI-тексты и документация — на русском (см. AGENTS).
- Имя отвечает на вопрос читателя, а не автора: `entryConflicts`, а не `flag`; `renamed`, а не `ok`.
- Сокращения запрещены, кроме общепринятых (`http`, `url`, `id`). Переменная-«текущий элемент» называется `current`, наблюдённое состояние — `observed`.

## 5. Исключения и коды ошибок

- Коды ошибок (`ha.entity.conflict`, `arr.endpoint.invalid`, ...) — часть контракта: не переименовываются и не объединяются при рефакторинге.
- Каждый страж бросает ровно одно исключение; последовательные стражи с одинаковым кодом допустимы и предпочтительнее пятистрочного `||`.
- Сообщения исключений не содержат секретов и тел ответов (см. AGENTS, раздел «Секреты»).

## 6. Тесты

- Тест подчиняется тем же правилам: один оператор на строку, читаемые arrange/act/assert.
- Имена тестов описывают сценарий и ожидание, а не механику вызовов.

## 7. Рефакторинг и форматирование

- Форматирование и чистка читаемости выполняются отдельным PR без логических изменений (см. AGENTS).
- Доказательство неизменности поведения — зелёные `dotnet build` и `dotnet test` до и после; расхождение останавливает слияние.
- Каждый рефакторинг-коммит указывает приём: «один оператор на строку», «декомпозиция условий» и т. п.
