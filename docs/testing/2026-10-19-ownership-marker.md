# Маркер владения установкой: read-only наблюдение

Дата: 2026-10-19. База: ветка PR #116 (`b960814`, проверка путей #49). Задачи: [#51](https://github.com/hhypest/hh-homelab-wizard/issues/51), prerequisites [#101](https://github.com/hhypest/hh-homelab-wizard/issues/101). SDK 10.0.401, SSH.NET 2026.0.0, build-time profile hh-homelab 1.3.0; зависимости не изменены. Решение: [ADR 0017](../adr/0017-installation-ownership-marker.md).

## Локальные fixtures

- Отсутствующий или пустой корень без маркера — новая установка; точное совпадение установки и профиля — своя установка.
- Маркер без ожидаемого владельца никогда не присваивается; чужая установка и смена профиля блокируют; непустой корень без маркера блокирует даже для ожидаемого владельца.
- `invalid`/`redirected`/`unavailable` блокируют соответствующими кодами.
- Недействительный маркер: пустой, массив, неполный, схема 2, схема-строка, не-GUID, пустой GUID, короткий отпечаток, лишнее или повторное свойство, данные после объекта, неверный UTF-8.
- Протокол: неизвестное состояние, `present` без содержимого, содержимое при `absent`, нечётная, верхнерегистровая или с пробелами hex-строка, hex больше 4096 байт, отсутствие строки маркера — весь ответ отвергается.
- Маркер входит в environment fingerprint; снимок не принимает некорректное наблюдение маркера; недопустимый ожидаемый владелец отвергается.
- Запрос содержит `owner=<корень конфигурации>` после путей; скрипт отвергает запрос без `owner` или с путём после него (код 2).

Скрипт запущен локально (Linux, dash) для своего, повреждённого, symlink и отсутствующего маркера; hex-вывод `od` совпадает с форматом, который разбирает production-парсер.

Локально Linux / SDK 10.0.401: locked restore, Release build без предупреждений и ошибок, все unit/fixture и Desktop тесты, JournalProbe и ProfileCheck. Docker daemon локально недоступен.

## Одноразовый OpenSSH-стенд в CI

Control plane от root записывает в `/volume1/docker` (tmpfs): свой маркер с профилем текущей сборки и файлом конфигурации, маркер другой установки, повреждённый маркер, каталог маркера через symlink и каталог маркера 0700. JSON передаётся control plane через stdin. Проба от пользователя `wizard` ожидает: own, not-adopted без владельца, profile-changed, foreign, marker-invalid, marker-redirected, marker-unavailable, unmarked-contents (`/volume1/docker/hh`) и new-installation для отсутствующего корня.

Результат CI, commit и definition hash фиксируются в PR и #51; наличие сценария не объявляется успешным прогоном.

## Не проверено

Создание маркера и remote lock (мутации, следующий инкремент), ownership контейнеров и отдельных ресурсов, DS725+/DSM ACL/sudo, поведение `od` в DSM.
