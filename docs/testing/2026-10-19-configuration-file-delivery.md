# Создание конфигурационного файла через журнал

Дата: 2026-10-19. База: `main` / `59f181f` (merge PR #121). Задачи: [#53](https://github.com/hhypest/hh-homelab-wizard/issues/53), prerequisites [#51](https://github.com/hhypest/hh-homelab-wizard/issues/51) и [#101](https://github.com/hhypest/hh-homelab-wizard/issues/101). SDK 10.0.401, SSH.NET 2026.0.0, build-time profile hh-homelab 1.3.0; зависимости не изменены. Решение: [ADR 0022](../adr/0022-configuration-file-delivery.md).

## Локальные fixtures

Настоящий `FileOperationJournal` во временном каталоге и `ConfigurationOperationScenario`. NAS — синтетический корень за поддельным SSH wire, который следует тем же правилам, что и скрипты.

- Новый файл: Applied, ровно одна запись точных байтов. Повтор — AlreadySatisfied без записи.
- Ответ потерян после записи: Unknown/WriteUncertain. Новый запуск с тем же журналом — Applied через наблюдение, запись по-прежнему одна.
- Канал оборвался после отправки без изменения: Unknown. Новый запуск повторяет условную запись под тем же intent — Applied.
- Другой файл, тот же файл с другим режимом, чужой маркер, корень без маркера, symlink на пути — Conflict без записи.
- Ручное изменение после создания: при resume — Conflict, изменённое содержимое не перезаписано.
- Доказанный отказ — Rejected/WriteRejected. Другой host key на соединении записи — Conflict/IdentityMismatch без записи. Сбой соединения до отправки — Transport без записи.
- Нечитаемый маркер и повреждённый ответ чтения не доказывают владение и не дают записи.
- Ресурс с другим endpoint или профилем отвергается при создании операции.
- Содержимое больше 64 KiB отвергается до копирования; `Dispose` обнуляет содержимое, дескриптор сохраняется; временный буфер запроса обнулён после отправки.
- Валидация пути: допускаются `media/compose.yaml`, `media/.env`, вложенные каталоги; отвергаются абсолютный путь, пустой компонент, `.`/`..`, каталог маркера, не-ASCII, пробел, больше 8 компонентов, компонент длиннее 64. Режим только 600/640/644. Пустой файл допустим.
- Спецификация меняется от содержимого, режима и пути; изменение буфера вызывающего после создания запроса не меняет запрос.
- Протокол: строки заголовка, затем ровно сырые байты; путь не попадает в текст команд. Подтверждение записи только при точном выводе; отказ только для кодов 2/3 без вывода; всё остальное — Unknown. Ответ чтения принимается только в точной форме: шестнадцатеричный хеш в нижнем регистре, восьмеричный режим, размер до 64 KiB, `not-checked` только для чужого корня.

## Скрипты на настоящем Linux

Запуск локально: dash как `/bin/sh` и bash, GNU coreutils.

- Чтение: файла нет — `absent`; после создания — `present:28:644:<sha256>`, совпадающий с `sha256sum` исходных байтов.
- Запись: создание с отсутствующим родителем `media/` — `file=created`; повтор — `already-present`; тот же путь с режимом 600 — отказ 3.
- Ручное дописывание строки: запись — отказ 3, чтение показывает новый размер и хеш.
- Чужой маркер: запись — отказ 3, чтение — `marker=different`, `file=not-checked`. Корень без маркера: `marker=absent`, запись — отказ 3.
- Каталог-symlink на `/tmp`: запись — отказ 3, в `/tmp` ничего не создано; чтение — `redirected`.
- Глубокий путь `media/config/qbittorrent/qb.conf` с режимом 600: файл 600, созданные каталоги 755.
- `../escape`, `.hh-homelab-wizard/x` и `a/../b` — код 2.
- Оборванное тело (5 байт вместо 28) и неверный SHA-256 — отказ 3. Цель и её каталог не созданы, в каталоге маркера осталось только `installation.json`.
- От `nobody` при корне, принадлежащем root, — отказ 3 без изменений.
- Байты, записанные под bash, совпадают с исходными (`cmp`).
- После автоматического ревью PR #122:
  - временное имя имеет режим 600 уже во время передачи (тело отправлялось с паузой);
  - замена существующего `media` на symlink во время передачи — отказ 3, каталог-цель symlink пуст, исходный каталог не изменён;
  - создание вложенных каталогов по одному работает, итоговый режим файла 600.
- После второго автоматического ревью (замечания пришли одновременно со слиянием PR #122, исправлены отдельным PR):
  - чтение: последний компонент — symlink на посторонний файл с теми же байтами — `redirected`; родитель-symlink — `redirected`;
  - `media/-f` — код 2 в обоих скриптах; C#-валидация отвергает компоненты с ведущим `-` и путь длиннее 255 до вычисления дескриптора;
  - во время передачи под конечным именем появились symlink на посторонний каталог или настоящий каталог: `ln -T` завершается ошибкой, исход Unknown, в посторонний каталог и внутрь нового каталога ничего не записано;
  - маркер заменён во время передачи — отказ 3, файл не создан.
- После ревью PR #123 (хеширование замедлено обёрткой `sha256sum`): файл переименован и заменён во время хеширования — `redirected`; файл удалён во время хеширования — `redirected`.

Локально Linux / SDK 10.0.401: Release build без предупреждений и ошибок, все unit/fixture и Desktop тесты. Docker daemon локально недоступен.

## Одноразовый OpenSSH-стенд в CI

ForceCommand исполняет embedded-копии тех же `nas-file-read.sh` и `nas-file-write.sh` (BusyBox Alpine); запрос остаётся на stdin. Проба от `wizard` выполняется после сценариев маркера и блокировки на собственном корне `/volume1/apps/created`. Журнал — новый каталог runner на каждый ресурс; повторное открытие журнала имитирует новый процесс. Ожидается:

1. `media/compose.yaml` (644): Applied, затем AlreadySatisfied;
2. `media/.env` (600) в режиме `file-lost-response`: скрипт действительно создаёт файл, ответ не приходит → Unknown/WriteUncertain при таймауте 3 с; после сброса — Applied через наблюдение, затем AlreadySatisfied;
3. пустой `media/config/qbittorrent/placeholder.conf` (600) с созданием вложенных каталогов — Applied;
4. control plane дописывает строку в `media/compose.yaml`; повтор — Conflict, чтение показывает размер с ручной строкой;
5. чужой маркер `/volume1/docker/foreign` и корень без маркера `/volume1/docker/hh` — Conflict;
6. `linked/compose.yaml`, где `linked` — symlink на `/volume1/apps/file-victim`, — Conflict, каталог-цель остаётся пустым.

Результат CI, commit и definition hash фиксируются в PR и #53; наличие сценария не объявляется успешным прогоном.
