# Preflight: модель NAS, порты и место томов

Дата: 2026-10-19. База: `ee17a40`, слияние PR #114 в `main`. Задачи: [#48](https://github.com/hhypest/hh-homelab-wizard/issues/48), prerequisites [#101](https://github.com/hhypest/hh-homelab-wizard/issues/101). SDK 10.0.401, build-time profile hh-homelab 1.3.0; версии устанавливаемых сервисов и зависимости не изменены. Решение: [ADR 0015](../adr/0015-preflight-host-resources.md).

## Локальные fixtures

- Протокол v2: модель, `listening`/`listen`, `volumes`/`volume`. Старый marker v1, неизвестный статус, пустая/некорректная модель, порт 0/65536/отрицательный, дубликат порта, список при `unavailable`, `available` больше общего объёма, нулевой объём, не-`/volumeN` mount, `/volume01`, неполная запись тома, повтор тома и пропущенный раздел отвергают весь ответ.
- 256 портов, 16 томов и 128 контейнеров одновременно принимаются и укладываются в 16 KiB; 257-й порт и 17-й том отвергаются.
- Без требований плана порты/место остаются NotChecked, модель — Unverified. Свободные порты и достаточное место дают Passed только своих проверок; paths/ACL/ownership остаются NotChecked.
- Конфликт порта блокирует и возвращает только конфликтующие порты. Отсутствующий том, нехватка места на 1 байт, нечитаемые слушатели/тома/модель блокируют. Пустой список слушателей допустим и отличается от `unavailable`.
- Изменение слушателей, общего объёма или модели меняет environment fingerprint, движение свободного места — нет. Требования копируются и валидируются.

Локальный запуск фиксированного скрипта на Linux с dash/mawk: настоящие `/proc/net/tcp`/`tcp6` разобраны в верные номера портов, ответ принят production-парсером. Синтетический вывод `df` проверил отбор только `/volume1` при наличии `/volumeUSB1/usbshare` и `/volume1/@docker`. Это проверка формата, не DSM.

Локально Linux / SDK 10.0.401: locked restore, Release build без предупреждений и ошибок, все unit/fixture и Desktop тесты, JournalProbe и ProfileCheck прошли. Docker daemon в среде разработки недоступен, поэтому SSH runtime локально не запускался.

## Одноразовый стенд в CI

Оба режима `ssh-runtime` используют обновлённый скрипт через прежний ForceCommand без изменений fixture-кода; definition hash стенда меняется вместе с embedded-копией. Дополнительно проверяется:

1. fixture sshd действительно слушает 2222 и он виден в снимке; модель Missing; `/volumeN` нет, но список томов доступен и пуст;
2. требование порта 2222 даёт `preflight.ports.conflict` и ровно `[2222]`, свободный 8123 — Passed;
3. требуемый `/volume1` даёт `volume-missing`: Linux-контейнер не выдаётся за DSM.

В режиме Docker те же проверки выполняются на каждом успешном снимке с настоящим daemon. Результат CI, commit и hash фиксируются в PR и #48; наличие сценария не объявляется успешным прогоном.
