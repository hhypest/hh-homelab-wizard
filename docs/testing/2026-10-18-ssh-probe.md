# Первый SSH-инкремент: fixtures и локальный TCP

Дата: 2026-10-18. База: PR #110, `cac10f0a1219c009b4f4fd5446d4d3daa7bca1ff`; новый PR направлен в его ветку, без слияния #109/#110. SDK — 10.0.401, SSH.NET — 2026.0.0; контракт и границы в [ADR 0012](../adr/0012-ssh-connection-probe.md). Точный head и CI результата фиксируются в PR/#46.

## Сценарии

- Первый ключ требует подтверждения до авторизации; следующий явный approved pin использует свежий transport. Изменённый ключ и pin другого endpoint блокируют соединение.
- SSH и SFTP требуют самостоятельной проверки ключа. Пропущенное evidence не даёт Ready. Нет автоматического agent/keyboard-interactive fallback.
- Неверные credentials, transport/SFTP failure, finite deadline на всех фазах, caller cancellation и второй конкурентный запуск имеют typed результаты; raw server errors/секреты не возвращаются.
- SSH.NET действительно разбирает сгенерированные в тесте RSA PKCS#8 keys с/без passphrase. Входной буфер можно очистить после создания credentials; используется собственная копия. Неверный key возвращает InvalidInput.
- Неверный marker/OS/UID/exit status и лишний вывод отвергаются. stdout/stderr ограничены; discarded stderr не декодируется/не публикуется. Успешный sudo listing не приравнивается к правам на установку.
- Настоящий SshClient подключается к собственному listener на 127.0.0.1 с динамическим портом: зависший handshake прекращается по deadline и по caller cancellation. SSH-сервер/авторизация в этом тесте не реализуются, credentials на wire не отправляются.

## Повторение

```text
dotnet restore HhHomelab.Wizard.slnx --locked-mode
dotnet build HhHomelab.Wizard.slnx --no-restore -c Release
dotnet test HhHomelab.Wizard.slnx --no-build -c Release
dotnet run --project tools/HhHomelab.Wizard.JournalProbe --no-build -c Release
dotnet run --project tools/HhHomelab.Wizard.ProfileCheck --no-build -c Release -- profiles/hh-homelab/1.3.0/research-profile.json
dotnet list HhHomelab.Wizard.slnx package --vulnerable --include-transitive --no-restore
```

Локальная среда — Windows; Linux, упаковка и прежние runtime jobs подтверждаются только отчётом соответствующего CI. Новый SSH порт не подключён к demo UI. Пользовательская [полная GUI-приёмка](../m1/2026-10-18-owner-check.md) относится к PR #110, сохраняется отдельно от проверок этого инкремента.

Не запускались успешный SSH/SFTP к живому серверу, Docker SSH стенд, NAS/DSM, sudo аппаратно, запись файлов, установка контейнеров и интегрированный resume по SSH. Эти пункты остаются #46/#48–#53/#101; fixture успех не закрывает задачи и этапы M2/M3.
