## Как принимать исправления

PR указывает ID находки, Issue, изменённое поведение, регрессионное доказательство и ограничения среды. Для частичного результата используется `Refs`, для полной приёмки — `Closes`. Не смешивать форматирование, архитектуру, транспортный bugfix и обновление versions в один трудно проверяемый PR. Намерения before-write, Observe после неизвестного исхода, ownership, TLS и гигиена секретов должны сохраниться.

Обновлены задачи #18–#21, #23, #40, #46–#55, #57–#59, #61, #63, #66, #77, #79, #86; созданы #96–#103 с существующими Milestones и метками. Ни одна продуктовая задача этим не закрыта. Project и native sub-issues/blocked-by не обновлены: доступный GitHub API не предоставляет эти операции. Родители, зависимости и рабочие статусы записаны в Issues; добавление карточек/связей и сверку доски выполнить при наличии соответствующего API, не считать уже выполненными.
