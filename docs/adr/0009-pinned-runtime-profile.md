# ADR 0009: снимок профиля и версии API

- Дата: 2026-10-18.
- Статус: принято для первого инкремента #100 по [ADR 0008](0008-audit-development-sequence.md).

## Причина

Образы находились в research profile, Docker-пробах и CI, а ожидаемые ответы version API — в клиентах. Эти копии можно было обновить независимо. Jellyfin, например, использует разные обозначения упаковки образа и версии API; выводить версию приложения простым удалением суффикса нельзя.

## Решение

Research profile получает схему 2. У сервисов с реализованной проверкой версии появляется `runtimeVersion`: точная строка ожидаемого ответа API. Для FlareSolverr и Socket Proxy поле отсутствует, поскольку текущие клиенты не доказывают их версию через такой ответ. Образ по-прежнему обязан иметь точный tag. `apiFamily` сохраняет обозначение контракта; маршруты и форма запросов остаются проверенным кодом адаптера.

Парсер продолжает читать схему 1 как исследовательский каталог без `runtimeVersion`. Она не выбирает runtime-контракты новых проб. Ненулевой runtimeVersion в схеме 1 отклоняется. Неизвестные поля и неподдерживаемые схемы по-прежнему запрещены. Формат lock Monitor Docker остаётся версией 1.

`PinnedRuntimeProfile` читает встроенный ресурс один раз. Его словари, строки, source/component records и коллекции Docker mods неизменяемы для потребителей. Клиенты получают ожидаемые версии, пробы — образы, Monitor Docker — commit/manifest из этого снимка. Lock компонента независимо сверяет repository/commit/manifest/license и контрольные суммы файлов до принятия архива; источник загрузки остаётся фиксированным HTTPS URL.

Проба с внешним JSON сначала проверяет его модель целиком по SHA-256 сериализованного типизированного профиля. Это отпечаток совместимости с конкретной сборкой: пробелы исходного JSON незначимы, порядок массивов и все поля модели значимы. Он не является подписью, проверкой Git checkout или долговечным форматом журнала. Внешний файл не заменяет встроенный снимок и не может менять pins посреди процесса.

CI получает список образов через `ProfileCheck --images`. Все выбранные сервисы проверяются до первого вывода. Ошибка выбора, несовместимость профиля или пустой вывод останавливают helper до Docker pull. Существующая политика повторов применяется только к получению образов. Два upstream checkout refs в CI пока явно закреплены; регрессионная проверка сверяет их с source commit профиля.

## Границы

Текущие image tags, mod/component pins, источник v1.3.0 и его fingerprints сохраняются. Изменение `schemaVersion` описывает формат каталога, а не новый состав или версию установленного hh-homelab. Загрузка новой версии требует изменения профиля, пересборки и проверки контрактов.

Роли, entity IDs, integration mapping, transforms, пути и счётчики остаются в #100. Фиксированный состав v1 сохраняется; optional graph 2.0.0 не реализуется этим решением. Модель операций #99, журнал #51 и вертикаль #101 используют этот фундамент отдельными инкрементами. Установка NAS и полная приёмка M0/M1 не входят в результат.
