# ADR 0008: приоритет вертикального сценария после аудита

- Дата: 2026-10-11.
- Статус: принято для организации разработки по заданию владельца об интеграции независимого аудита; реализация и испытания ещё не выполнены.
- Основание: [источник аудита](../audit/2026-10-11-independent-review.md), [решения по находкам](../audit/2026-10-11-follow-up.md), #96.

## Проблема

M0 углубляет контракты HA, пока SSH, Application-порты, план и долговечный журнал существуют только в документах. Формальная зависимость начала всей M2 от полного M0/M1 задерживает проверку формы адаптеров из-за несвязанных аппаратных и клиентских испытаний. Состояние операций в памяти клиентов несовместимо с resume между процессами.

## Решение

1. Сначала исправить B1/B2 в #97; перенос на общий транспорт выполнять небольшими PR после регрессионного доказательства. Не ждать полного архитектурного рефакторинга ради исправления таймаутов.
2. В #99 определить модели и типизированные исходы Domain, порты Observe/Apply/Verify и сценарий Application. Клиенты Infrastructure реализуют порты; длительное намерение принадлежит журналу #51. В #100 согласовать versions/API contracts/roles между профилем, клиентами, probes и CI.
3. Ранний runnable результат #101: один qBittorrent через SSH → read-only preflight → конкретный план → атомарный intent → доставка/Compose → configuration → verify → confirm → новый процесс/resume. Использовать минимальные инкременты существующих #46–#54, а не второй движок ради пробы.
4. Design/fixture PR для M2/M3 и одноразовый SSH/Docker стенд допускаются до полной приёмки M0/M1. Первая вертикаль не требует исследования всех устройств HA. Необходимые аппаратные неизвестные M0 продолжаются отдельно.
5. **Условия завершения** M0/M1, интеграционного M2/M3 и последующих этапов сохраняются. Native blocked-by родительских эпиков описывают полную приёмку. В Issue и PR независимого инкремента явно указывать, какая часть разрешена до неё. Реальная DSM-установка требует готовности обязательных механизмов M3, согласованной среды и конкретного авторизованного плана; запрос на интеграцию аудита не является заданием на установку NAS.

## Инварианты

- Намерение атомарно фиксируется до отправки, подтверждение — после независимой проверки; version/hash/ownership обязательны даже в минимальном журнале.
- Timeout, потеря ответа и отмена ожидания после отправки не доказывают отсутствие записи. Unknown разрешает Observe, а не слепой повтор Apply.
- HTTP 4xx даёт Rejected только при доказанном отказе до изменения по контракту закреплённой версии. Неоднозначный ответ сохраняет Unknown.
- Host key, resource identity, секреты, чужие ресурсы, пути и медиатека защищаются так же, как в [ADR 0002](0002-journal-and-secrets.md). Изолированность стенда не оправдывает обход этих правил.

## Последствия

Критический путь становится проверяемым раньше, полная матрица приёмки остаётся открытой. Дополнительные HA-контракты реализуются после обратной связи вертикали; #102 разделяет HA-клиент перед M5. Фиксированный состав v1 сохраняется, data-driven выбор 2.0.0 выполняется в V2 после M8; параметры устройств и pins готовятся уже в v1.

Читаемость/CI #98 выполняются отдельными PR; форматирование не смешивается с исправлением поведения. [STATUS](../STATUS.md) хранит текущую готовность, протоколы — исторические доказательства, Issues — рабочие статусы. При недоступном Project/native API актуальное состояние явно сохраняется в Issue, а обновление доски не заявляется.
