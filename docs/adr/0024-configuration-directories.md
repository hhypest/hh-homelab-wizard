# ADR 0024: создание конфигурационных каталогов через журнал

- Дата: 2026-10-19.
- Статус: разработческий инкремент [#53](https://github.com/hhypest/hh-homelab-wizard/issues/53) для вертикали [#101](https://github.com/hhypest/hh-homelab-wizard/issues/101); fixtures и одноразовый стенд по [ADR 0008](0008-audit-development-sequence.md).
- Основа: [создание файла](0022-configuration-file-delivery.md), [маркер](0017-installation-ownership-marker.md), [граф](0020-configuration-plan-recovery.md).

## Решение

Каталоги монтирования qBittorrent (`media/config/qbittorrent`, `media/watch`) должны существовать до запуска контейнера: иначе Docker создаст их сам от root, с чужим владельцем. Создание одного каталога — обычная операция `ConfigurationDirectory` сервиса `nas` в общем сценарии Observe → intent → Apply → Verify → confirm.

`ConfigurationDirectoryRequest` связывает корень конфигурации, относительный путь, режим и владельца. Правила пути те же, что у файлов ADR 0022, плюс запрет компонентов с ведущим `-`. Режим — только 700, 750 или 755. Путь длиннее 255 символов отвергается до вычисления дескриптора.

`nas-directory-read.sh` (read-only) сверяет маркер побайтно. Только для корня этой установки он входит в каждый каталог (`cd -P`, сверка `pwd -P`) и сообщает `absent`, `present:<режим>`, `not-directory`, `redirected` или `unavailable`. Содержимое каталога не перечисляется.

| Наблюдение | Состояние |
| --- | --- |
| Свой маркер, каталога (или его родителя) нет | Missing |
| Свой маркер, каталог с этим режимом | Satisfied |
| Другой режим, файл на пути, symlink | Conflict |
| Чужой корень, корень без маркера | Conflict (владение не доказано) |

Существующий каталог с другим режимом **не меняется**: ни chmod, ни chown, ни очистки. Рекурсивных изменений нет.

`nas-directory-create.sh` получает корень, маркер, путь и режим через stdin. До изменения он проверяет маркер и каноничность корня, затем проходит существующие компоненты через `cd -P` со сверкой `pwd -P`. Если весь путь уже есть, принимается только тот же режим (`already-present`). Перед первым изменением маркер проверяется снова, а самый глубокий существующий каталог должен быть доступен для записи. Отсутствующие родители создаются относительно текущего каталога с режимом по умолчанию 755. Сам каталог создаётся сразу с нужным режимом (`mkdir -m`), поэтому никогда не существует с более широким. После создания режим и маркер проверяются ещё раз.

Исходы как у файла: код 2/3 без вывода — Rejected, ничего не изменилось; сбой до передачи — NotSent; другой host key — Conflict/IdentityMismatch; всё после отправки — Unknown, затем подтверждение наблюдением. Операция поддерживает `IRepeatableConditionalApply`.

Скрипты используют отдельный интерфейс `INasDirectoryWire`, поэтому существующие wire и тестовые подделки не меняются.

## Границы

- Каталоги создаются пользователем SSH, без sudo и chown. Если PUID/PGID контейнера отличаются от пользователя SSH, контейнер может не получить права записи. Это пока не проверяется и остаётся частью #49 и PUID/PGID-проверки плана.
- Каталоги данных под корнем данных (`PreserveOrCreate`) этим запросом не создаются: они вне собственного маркера и требуют отдельной политики.
- Удаление и компенсация не реализованы. Шаги каталогов в графе ADR 0023 — следующий инкремент после слияния обоих PR.
- DSM ACL и `mkdir -m` на DSM не проверены.
