# ADR 0016: read-only проверка путей медиатеки и конфигурации

- Дата: 2026-10-19.
- Статус: частичный инкремент [#49](https://github.com/hhypest/hh-homelab-wizard/issues/49), design/fixtures и одноразовый стенд по [ADR 0008](0008-audit-development-sequence.md).
- Основа: [SSH-порт](0012-ssh-connection-probe.md), [preflight](0013-read-only-nas-preflight.md), [ресурсы NAS](0015-preflight-host-resources.md).

## Раскладка

Пользователь выбирает два корня на NAS: общий корень данных и корень конфигурации. `MediaPathLayout` принимает только абсолютные нормализованные пути ниже `/volumeN` без пустых, `.`/`..`, управляющих и `\` компонентов, без завершающего `/`; пробелы и кириллица допустимы. Компонент ограничен 255 байтами UTF-8 (лимит файловой системы считается в байтах, непарный суррогат отвергается), корень — 32 компонентами; глубина наблюдения допускает ещё два фиксированных уровня подкаталогов. Корни не могут совпадать или вкладываться друг в друга.

Подкаталоги данных фиксированы и совпадают с уже принятыми контрактами контейнеров: `torrents/{movies,tv}` → `/data/torrents/...` (qBittorrent) и `media/{movies,tv}` → `/data/media/...` (Arr/Jellyfin). Раскладка конфигурации по сервисам и PUID/PGID контейнеров принадлежат профилю (#100) и здесь не выдумываются.

## Передача путей

Пути — пользовательский ввод, поэтому команда остаётся фиксированным embedded-скриптом, а пути передаются через **stdin** строковым запросом `nas-paths-request:v1` (до 8 путей, `end`). Скрипт только цитирует их в `test`/`stat`/`cd -P`/`ls -A`, ничего не исполняет из запроса, при нарушении формата завершается с кодом 2. Ответ не повторяет пути и имена файлов: сначала устройство `/`, затем по индексу запроса только тип, глубина ближайшего существующего предка, `same`/`redirected`, устройство, uid/gid, восьмеричный mode и пусто/непусто. Неполный, повреждённый ответ или ненулевой код отвергают весь снимок.

## Наблюдение

- Отсутствующий путь описывается ближайшим существующим предком: его устройство и права унаследует создаваемый позже каталог. Предок выше точки монтирования тома означает отсутствующий том.
- Каталог без права поиска даёт `unavailable`: SSH-пользователь не может отличить отсутствие от скрытого содержимого.
- Symlink в самом пути или любом предке (`cd -P`/`pwd -P` ≠ лексический родитель) даёт `redirected` и блокирует: проверка после разрешения ссылок требует, чтобы выбранный путь и был реальным.
- Файл вместо каталога (сам путь или предок) — `not-directory`.
- Содержимое проверяется только для существующих каталогов и только на пустоту: считается первый байт вывода `ls -A`, поэтому имя из одних переводов строки не выглядит пустым каталогом. Существующий каталог, который нельзя прочитать или обойти, блокирует свою роль.
- Путь, существующий предок которого лежит на устройстве `/`, находится в оставшемся каталоге точки монтирования, а не на смонтированном томе (`volume-unmounted`): иначе установка могла бы писать в системный раздел.

## Оценка

Существующая медиатека и загрузки разрешены. Непустой корень конфигурации блокируется как `ownership-required`: в нём могут быть базы приложений или чужой стек; продолжение собственной сессии позже решает ownership #51–#53, не эвристика по именам файлов. Начиная с [ADR 0017](0017-installation-ownership-marker.md) эту оценку выполняет маркер владения: коды `paths.configuration-root.*` заменены на `ownership.*` до слияния в `main`.

Все каталоги данных должны иметь одно устройство (`st_dev`): на DSM общая папка — отдельный btrfs subvolume, и hardlink при импорте Arr между ними невозможен. Это необходимое, не достаточное условие: реальный hardlink проверяется в M4/M7 на разрешённом тестовом файле.

`paths.permissions` всегда Unverified: POSIX mode не доказывает доступ контейнера с ещё не закреплёнными PUID/PGID. `paths.dsm-acl` — NotChecked: DSM ACL не видны через mode, а `synoacltool` не подтверждён аппаратно. Recursive chmod/chown, создание каталогов и sudo не выполняются.

Снимок привязан к endpoint, host key, SSH-пользователю и профилю: доступность и содержимое зависят от учётной записи. Environment fingerprint включает раскладку, устройство `/` и все наблюдения. Это не разрешение Apply: перед изменениями нужна новая проверка.

## Границы

Стенд — Linux-контейнер с одним overlay-устройством: несовпадение устройств проверяется fixtures. DS725+, btrfs subvolumes, DSM ACL, `@eaDir` и поведение busybox/coreutils DSM не подтверждены. Полные #49, M2 и #101 не закрываются; план и UI — #50.

Текущая версия протокола — v3 с обязательной numeric SSH identity по [ADR 0025](0025-container-unix-identity.md); выше сохранено описание исходного инкремента.
