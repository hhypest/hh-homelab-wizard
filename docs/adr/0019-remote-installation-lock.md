# ADR 0019: удалённая блокировка установки на NAS

- Дата: 2026-10-19.
- Статус: инкремент [#51](https://github.com/hhypest/hh-homelab-wizard/issues/51) на fixtures и одноразовом стенде по [ADR 0008](0008-audit-development-sequence.md); реальный NAS не изменяется.
- Основа: [локальный журнал](0011-local-file-journal.md), [маркер владения](0017-installation-ownership-marker.md), [создание маркера](0018-ownership-marker-creation.md).

## Проблема

Локальный lease журнала исключает второй процесс на одном компьютере, но не второй компьютер с собственным журналом. Два мастера одной установки могли бы одновременно менять одни ресурсы NAS.

## Решение

Блокировка — каталог `<корень конфигурации>/.hh-homelab-wizard/lock/` с файлом `holder`, в котором только session GUID. Она существует **только внутри собственного маркера**: скрипт сначала сверяет маркер побайтно с ожидаемым (установка и профиль), иначе `not-owned`. Создание самого маркера блокировка не защищает — его атомарность уже даёт публикация `ln` (ADR 0018).

Фиксированный `nas-lock.sh`, действие, корень, ожидаемый маркер и сессия — через stdin:

- **acquire**: атомарный `mkdir lock`; затем holder записывается через временный файл и `mv`. Существующая блокировка того же session GUID — `reacquired`: исключительность этой сессии на её компьютере уже гарантирует локальный lease, а прерванный процесс той же сессии должен продолжить. Чужая — `held:<GUID или unknown>:<возраст в секундах по часам NAS>`.
- **release**: только своя (`released`), отсутствующая — `not-held`, чужая — отказ `held`.
- Корень должен быть каноничным (`cd -P`/`pwd -P` совпадает с путём): symlink у любого предка — `invalid` до доступа к маркеру. Маркер сверяется побайтно через hex-кодировщик после проверки размера ≤ 4096, а не через переменную shell. Symlink на пути маркера/блокировки, каталог без прав записи — `invalid`. Holder возвращается только если файл ровно 36 байт и это строчный GUID; иное содержимое (в том числе GUID с переводом строки или NUL, которые теряет подстановка команды) — `unknown`, такую блокировку не захватывает и не снимает даже та же сессия.

Код 3 — отказ до изменений, 0 — точный успех; любой другой код, вывод или обрыв **после** отправки — `Unknown` (блокировка могла быть взята). До отправки — `NotSent`; host key, не совпавший с pin, — отдельный `IdentityChanged` (смена идентичности NAS, не транспорт), запрос не отправляется.

Чужая блокировка **никогда** не снимается автоматически, независимо от возраста: решение о переходе — действие пользователя (будущий UI). Каталог блокировки без holder после прерывания между `mkdir` и записью — `held:unknown`, блокирует и ту же сессию.

## Встраивание

`RemoteLockedOperationJournal` — декоратор `IOperationJournal`: сначала локальный lease, затем удалённая блокировка; она держится на всё Observe/Apply/Verify/confirm и снимается перед локальным lease (на освобождение не действует отмена вызывающего). Отмена вызывающего до доставки запроса — `OperationCanceledException` (Cancelled); любой другой результат, кроме `acquired`/`reacquired`, — `OperationLeaseUnavailableException`, то есть сценарий завершается `Conflict/OperationInProgress` до первого шага. Сценарий и операции не меняются.

Неудачное освобождение оставляет блокировку своей сессии: та же сессия возьмёт её снова, другая увидит занятой.

## Границы

Блокировка добровольная: она защищает от второго мастера, а не от ручных изменений пользователя NAS. Нет lease/heartbeat по времени и автоматического восстановления зависшей блокировки; нет проверки удержания внутри каждого шага (её снятие посторонним во время операции не обнаруживается до release). Нет fsync каталога. DSM ACL, PUID/PGID и утилиты DSM не подтверждены. UI выбора «перехватить блокировку» и recovery #52 — отдельные задачи; полные #51/M3 не закрываются.
