# ADR 0020: неизменяемый граф конфигурации и восстановление

- Дата: 2026-10-19.
- Статус: разработческий инкремент [#52](https://github.com/hhypest/hh-homelab-wizard/issues/52), prerequisites #51, родитель #21, вертикаль #101; fixtures и локальная process-restart проба по [ADR 0008](0008-audit-development-sequence.md).
- Основа: [операция](0010-operation-boundaries.md), [файловый журнал](0011-local-file-journal.md), [удалённая блокировка](0019-remote-installation-lock.md).

## Решение

`ConfigurationOperationPlan` — ограниченный граф обязательных операций одной установки/профиля: descriptor, GUID зависимостей и положительный бюджет до часа на шаг. Входные коллекции копируются и выдаются только для чтения. До обращения к журналу отвергаются пустой граф, дубли, неизвестные зависимости, циклы и противоречивая resource identity. Максимум — 1024 шага. Порядок входных шагов определяет стабильный выбор среди доступных; зависимости выполняются раньше потребителя.

Отпечаток включает весь упорядоченный список descriptor, отсортированные зависимости и точные ticks бюджета. Параметры адаптера уже включены в `SpecificationHash`; секретов в плане нет. Изменение состава, зависимостей, identity, параметров или бюджета требует другого плана и несовместимо с прежним журналом.

`ConfigurationPlanScenario` сначала проверяет весь набор адаптеров, затем вызывает обязательный `IOperationPlanJournal.BindPlanAsync`. После этого последовательно вызывает существующий `ConfigurationOperationScenario` для каждого шага в топологическом порядке. Другого пути Apply нет. Одновременный запуск того же экземпляра отклоняется. Перед каждым шагом повторно сверяется descriptor адаптера.

Любой неуспех останавливает весь граф, в том числе независимые ветви. Не начатые шаги не считаются выполненными и не попадают в список попыток. Отчёт сохраняет итог каждого уже начатого шага, поэтому остановка после успеха не теряет выполненные изменения. Отмена между шагами останавливает следующий; отмена после intent остаётся Unknown по правилам однооперационного сценария. Это не rollback.

Бюджет кооперативный: связанный CancellationToken передаётся в существующие порты. Истечение до intent — `Transport/DeadlineExceeded`, отмена вызывающего до intent — `Cancelled`, pending intent — `Unknown`. UI предлагает проверить соединение для DeadlineExceeded; Unknown по-прежнему требует наблюдения. Принудительного завершения произвольного адаптера, игнорирующего токен, нет.

## Сохранение и продолжение

Локальный журнал использует **schema 2**: envelope содержит nullable `Plan`, а при привязке — полный граф и его отпечаток. Привязка публикуется атомарно под тем же межпроцессным файловым lock до первого intent. Непустая история одиночных операций не присваивается новому графу. Повторная привязка того же графа ничего не пишет; другой отпечаток даёт `Conflict/IdentityMismatch` до Observe.

На каждом чтении журнала проверяются checksum, scope, семантика графа и его отпечаток, принадлежность entries плану. Lease не допускает descriptor вне плана, даже если одиночный сценарий вызван напрямую. Последующие intent/confirm сохраняют привязку графа.

**Schema 1 не мигрируется и не сбрасывается автоматически.** Старый файл остаётся без изменений; продолжать такую сессию новой сборкой нельзя. Перед дальнейшей приёмкой нужен отдельный проверенный перенос схемы, если потребуется продолжение старых исследовательских журналов. Удалять журнал прерванной установки для обхода отказа нельзя. Маркер NAS сохраняет собственную schema 1: формат маркера этим решением не меняется.

После перезапуска заново передаются тот же план, scope и адаптеры. Каждый шаг, включая подтверждённый, снова проходит ownership/Observe/Verify. Pending + Satisfied подтверждается без второго Apply; pending + Missing остаётся Unknown, кроме уже существующего opt-in условной no-clobber записи из ADR 0018. Исчезнувшая подтверждённая зависимость блокирует последующие шаги. Успех из прошлой памяти или журнала не заменяет свежее наблюдение.

`RemoteLockedOperationJournal` передаёт локальную привязку внутреннему plan-capable журналу; удалённая блокировка сохраняет прежнюю область — одна операция целиком. Между шагами lease освобождается: граф не является транзакцией NAS, не обеспечивает непрерывную блокировку всего графа и не защищает от ручного изменения после проверки зависимости. Каждое изменение по-прежнему требует собственного свежего ownership/baseline. Новых удалённых команд нет.

## Границы

Это исполнитель ограниченных конфигурационных операций, ещё не компилятор конкретного плана установки #50. Ожидание PIN/ввода, Desktop wiring, Compose/SFTP delivery, compensation и полноценная вертикаль qBittorrent остаются открытыми. Полная #52/M3 не закрывается. Power-loss durability/fsync каталога и реальная DSM не доказаны. Процессная проба использует синтетический внешний ресурс; она не является SSH/NAS испытанием.
