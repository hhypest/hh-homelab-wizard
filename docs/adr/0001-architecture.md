# ADR 0001: границы первого кода

Статус: принято для начала M0, 2026-10-10.

Историческое описание первого кода ниже относится к M0. С 2026-10-11 Application/Desktop и UI-пакеты добавлены первым каркасом M1, см. [ADR 0006](0006-desktop-demo.md); SSH-библиотека и реальные сценарии установки ещё не выбраны/не реализованы.

Установка должна работать с двух клиентских ОС и продолжаться после потери связи. Логика не может зависеть от окон Avalonia.

Решение: Domain описывает профиль и правила; Application будет содержать сценарии и интерфейсы адаптеров; Infrastructure — транспорт и хранение; Desktop — Views, ViewModels и composition root. MVVM обязателен при появлении UI. Сейчас созданы только Domain, Infrastructure, developer tools и тесты. Не создаём пустые Application/Desktop ради видимости готового каркаса.

Основа первых проб — .NET SDK 10.0.401 / net10.0, без preview и внешних runtime-зависимостей. Тесты используют закреплённые Microsoft.NET.Test.Sdk 18.0.1, xunit.v3 3.2.1 и VS runner 3.1.5; версии выбраны для проверяемой текущей сборки, не объявлены самыми новыми. Используются central package management и lock-файлы. Avalonia, Toolkit и SSH-библиотека выбираются в M1 после проверки совместимости.

`ResearchProfile` — версия 1 схемы исследовательского каталога. Схема 2 и чтение прежнего каталога уточнены [ADR 0009](0009-pinned-runtime-profile.md). Первый формат учитывает provenance, контрольные суммы UTF-8/LF, контейнеры, моды, сторонние компоненты и покрытие инструкции. Это не installation plan: валидный каталог не разрешает установку и не содержит credentials. C#-парсер отклоняет неизвестные поля, неподдерживаемую схему, неправильные ссылки и дубли.

Канонизация текстовых файлов позволяет сравнивать checkout с CRLF на Windows и LF на Linux. Она не проверяет подпись tag, происхождение локального checkout или всю историю Git. Исполняемая доставка источника потребует отдельной проверки происхождения в M2.

Последствие: первые инструменты доступны разработчикам с SDK; пользовательского установщика пока нет. Перенос проб в полноценные адаптеры требует портов Application, правил журнала и проверки контрактов каждого шага.
