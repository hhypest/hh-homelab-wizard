# ADR 0022: создание конфигурационного файла через журнал

- Дата: 2026-10-19.
- Статус: первый ограниченный инкремент [#53](https://github.com/hhypest/hh-homelab-wizard/issues/53) (A6), prerequisites #51, родитель #21, вертикаль #101; fixtures и одноразовый стенд по [ADR 0008](0008-audit-development-sequence.md).
- Основа: [операция](0010-operation-boundaries.md), [маркер владения](0017-installation-ownership-marker.md) и [его создание](0018-ownership-marker-creation.md), [граф](0020-configuration-plan-recovery.md), [план qBittorrent](0021-qbittorrent-installation-plan.md).

## Решение

Создание одного файла этой установки — обычная операция `ConfigurationFile` сервиса `nas` в общем `ConfigurationOperationScenario`: свежее Observe → атомарный intent → Apply → независимый Verify → confirm. Второго пути исполнения нет; в графе ADR 0020 файл становится шагом после маркера.

`ConfigurationFileRequest` содержит корень конфигурации, относительный путь, режим, точное содержимое и владельца. Спецификация (и `SpecificationHash`) связывает корень, путь, режим, длину, SHA-256 содержимого, installation ID и профиль; содержимое копируется при создании. Ограничения:

- путь — от 1 до 8 компонентов из ASCII-букв, цифр, `.`, `_`, `-`, не длиннее 64 символов каждый и не длиннее 255 символов целиком (проверяется до хеширования); без `.`/`..`, пустых компонентов, компонентов, начинающихся с `-` (утилиты не примут имя за опцию), и без каталога `.hh-homelab-wizard`. Кириллица в именах файлов не поддерживается: так путь означает одни и те же байты для shell и парсера;
- режим только 600, 640 или 644; каталоги, владельцы и специальные биты этим запросом не задаются;
- содержимое не больше 64 KiB; граница проверяется до копирования и хеширования.

Файл может содержать секреты, поэтому содержимое хранится в собственном буфере запроса и обнуляется при `Dispose`; дескриптор для журнала остаётся. Временный буфер запроса SSH обнуляется сразу после отправки. Копии внутри SSH.NET и операционной системы этим не контролируются; жизненный цикл секретов — #47.

Файлы шаблона qBittorrent (`media/compose.yaml`, `media/.env`) лежат в этих границах. Рендер содержимого из плана ADR 0021 — следующий инкремент; этот ADR доставляет уже готовые байты.

### Наблюдение

Фиксированный read-only `nas-file-read.sh` получает корень, ожидаемый маркер и путь только через stdin. Сначала он сверяет маркер побайтно и проверяет, что существующий корень каноничен (`cd -P`/`pwd -P`). Только при точном совпадении маркера он проходит путь по компонентам: входит (`cd -P`) в каждый каталог и сверяет `pwd -P`, а сам файл открывает один раз и сверяет его реальный путь через `/proc/self/fd`. Размер, режим и хеш читаются уже из открытого дескриптора, поэтому подмена компонента на symlink во время чтения даёт `redirected`, а не данные постороннего файла. После хеширования путь дескриптора и совпадение inode с именем проверяются ещё раз: файл, удалённый или переименованный во время чтения, тоже даёт `redirected`. Скрипт сообщает `absent`, `present:<размер>:<режим>:<sha256>`, `not-regular`, `redirected`, `unavailable` или `oversized`. Содержимое файла не передаётся. Для чужого или неподтверждённого корня файл не читается (`not-checked`). Ответ строго четырёхстрочный; любое отклонение отвергает наблюдение целиком.

| Наблюдение | Состояние операции |
| --- | --- |
| Свой маркер, файла нет (в том числе нет родительских каталогов) | Missing |
| Свой маркер, точно эти байты и режим | Satisfied |
| Другой файл или режим, symlink/не каталог на пути, файл больше 64 KiB | Conflict |
| Чужой маркер, корень без маркера, symlink-корень | Conflict (владение не доказано) |
| Маркер нельзя прочитать | Владение не доказано |

Более позднее ручное изменение созданного файла видно как Conflict при следующем Observe или resume и **никогда не перезаписывается** этой операцией. Замена файла, backup и компенсация — отдельные будущие решения.

### Запись

Фиксированный `nas-file-write.sh` получает строки запроса (корень, маркер, путь, режим, размер, SHA-256), затем ровно указанное число сырых байтов. Кодирование не требуется, путь не попадает в командную строку. До изменения цели скрипт проверяет:

1. symlink корня, каталога маркера и маркера, каноничность корня, точный маркер и право записи в каталог маркера;
2. каждый существующий родительский каталог: настоящий каталог с правом обхода, не symlink; самый глубокий существующий должен быть доступен для записи;
3. существующий файл: те же байты и режим — `already-present` (код 0); другое — отказ (код 3).

Содержимое принимается в новое приватное имя внутри собственного каталога `.hh-homelab-wizard`: создание эксклюзивное (noclobber), режим с самого создания 600 (`umask 077`), поэтому секрет не читается другими пользователями во время передачи. Затем имя получает запрошенный режим и сверяется по размеру и SHA-256. Оборванная передача или несовпадение дают отказ 3; временное имя удаляется при выходе. Цель и её каталоги до этого момента не меняются.

Публикация не использует проверенный ранее путь целиком. Скрипт входит (`cd -P`) в самый глубокий существующий родитель и сверяет его разрешённый путь (`pwd -P`) с ожидаемым. Несовпадение, например родитель, заменённый на symlink во время передачи, — отказ 3 до любого изменения. Отсутствующие каталоги создаются относительно текущего каталога по одному, с той же сверкой после входа в каждый; файл публикуется hard link без замены (`ln`) по имени в текущем каталоге. Так подмена проверенного родителя не может перенаправить запись за пределы корня.

Маркер и каноничность корня проверяются ещё раз непосредственно перед первым изменением: маркер, заменённый во время передачи, даёт отказ 3. `ln -T` не принимает имя, созданное кем-то за это время (даже каталог или symlink на каталог), как каталог назначения. После публикации скрипт сверяет байты и режим опубликованного имени и снова проверяет маркер; несовпадение — исход Unknown, а следующее наблюдение покажет Conflict. Между последней проверкой маркера и `ln` остаётся микроокно: атомарной блокировки от ручных изменений на NAS нет, другие экземпляры мастера исключает удалённая блокировка (ADR 0019). Если кто-то создал файл между проверкой и публикацией, `ln` не заменяет его, исход — Unknown, и следующее Observe покажет Satisfied или Conflict.

Исходы такие же, как у маркера (ADR 0018):

- точный вывод при коде 0 — подтверждение команды; успех даёт только Verify;
- код 2/3 без вывода — Rejected, доказано, что цель не менялась;
- сбой до полной передачи stdin — NotSent (Transport);
- другой host key на соединении записи — `IdentityChanged` (Conflict/IdentityMismatch);
- всё после отправки — Unknown, затем новое Observe без слепого повтора.

Операция реализует `IRepeatableConditionalApply`: если при pending intent свежее Observe снова видит Missing, условная запись повторяется под тем же intent; любой сбой повтора остаётся Unknown.

## Границы

- Это только создание. Замена существующего файла (compare-and-swap по прежнему хешу), backup, компенсация и удаление не реализованы: критерии #53 о backup и компенсации остаются открытыми. Откат созданного файла не обещается.
- Каталоги создаются с umask 022 (0755) и владельцем — пользователем SSH. PUID/PGID контейнеров, DSM ACL и sudo не применяются и не проверены.
- Hard link требует, чтобы каталог маркера и цель были на одной файловой системе; иначе `ln` завершается ошибкой, исход Unknown.
- Утилиты `stat -c`/`-L`, `head -c`, `sha256sum`, `od`, `readlink`, `ln -T` и `/proc/self/fd` на DSM не проверены. На стенде используется BusyBox Alpine, локально — GNU coreutils с dash и bash.
- fsync файла и каталога не выполняется: устойчивость к сбою питания не доказана.
- Если процесс убит сигналом, который нельзя перехватить, приватное временное имя может остаться в `.hh-homelab-wizard`. Цель от этого не меняется.
