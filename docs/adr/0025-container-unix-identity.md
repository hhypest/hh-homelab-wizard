# ADR 0025: числовая identity SSH и PUID/PGID контейнера

- Дата: 2026-10-19.
- Статус: частичный инкремент [#49](https://github.com/hhypest/hh-homelab-wizard/issues/49)/[#50](https://github.com/hhypest/hh-homelab-wizard/issues/50) для вертикали [#101](https://github.com/hhypest/hh-homelab-wizard/issues/101), родители #20/#21; fixtures и одноразовый SSH-стенд по [ADR 0008](0008-audit-development-sequence.md).
- Основа: [проверка путей](0016-remote-path-inspection.md), [план](0021-qbittorrent-installation-plan.md), [граф](0023-qbittorrent-configuration-graph.md), [каталоги](0024-configuration-directories.md).

## Проблема

Граф создаёт `/config` и `/watch` пользователем SSH с режимом 750, без sudo/chown. Раньше запрос мог выбрать другой PUID: даже успешно созданный каталог не становился доступным контейнеру для записи. Имя SSH-пользователя не доказывает его текущий числовой UID, а UID/GID ближайшего существующего предка отсутствующего каталога вообще относятся к другому объекту.

## Решение

Read-only `nas-paths-request:v3` / `nas-paths:v3` добавляют обязательную строку `identity=<uid>:<primary-gid>` после устройства `/`. Фиксированный скрипт читает `id -u` и `id -g` в той же SSH-сессии до выдачи ответа; сбой любого чтения отклоняет весь снимок. Пути по-прежнему передаются через stdin, новых команд записи нет. Предыдущие версии запроса/ответа не принимаются: отсутствие identity нельзя молча заменить владельцем каталога или значением по умолчанию.

`RemoteUnixIdentity` хранит два неотрицательных int. Parser ограничивает каждое число десятью десятичными цифрами и диапазоном int; отрицательные, неполные/лишние поля и переполнение отвергаются. Наблюдаемый root (0) допустим как факт, но контейнерный запрос по-прежнему запрещает PUID/PGID=0. Snapshot дополнительно валидирует identity при прямом создании без parser, копирует неизменяемое значение и включает его в environment fingerprint. Имена, пароли и список групп в протокол не добавляются.

Для **первой поддерживаемой политики графа** PUID равен наблюдаемому UID, PGID — наблюдаемой основной GID:

| Проверка | Совпадение | Несовпадение |
| --- | --- | --- |
| `plan.puid.ssh-user` | Passed только для равенства ID | `.mismatch`, Blocking |
| `plan.pgid.ssh-primary-group` | Passed только для равенства ID | `.mismatch`, Blocking |

Отдельная, в том числе дополнительная, группа контейнера пока не поддерживается этой политикой. Это консервативное ограничение первого графа, а не утверждение, что любой другой PGID обязательно лишает доступа. Выбор другого пользователя/группы требует отдельного проверенного контракта создания и доступа, вместо автоматического chown или расширения прав. Значения запроса не подменяются наблюдаемыми автоматически.

`QbittorrentInstallationGraph.Create` уже отклоняет любой Blocking-план, поэтому несовпадение останавливает создание графа до journal/marker/directory/file writes. Перепроверка плана заново получает identity: перенумерация UID/GID при прежнем имени и путях меняет fingerprint и результат проверок. Владельцы существующей медиатеки не сравниваются с PUID с целью присвоения; жизненный цикл данных прежний.

## Границы доказательства

Совпадение UID/GID доказывает только числовое соответствие выбранной политике. `paths.permissions` остаётся Unverified, `paths.dsm-acl` — NotChecked. Не проверены фактическая запись из контейнера, supplementary groups, user namespace/rootless mappings, ACL, унаследованные setgid groups, доступ ко всем предкам и hardlink как операция. Primary GID процесса не обещает GID каждого созданного каталога при setgid наследовании.

Граф по-прежнему не запускает контейнер. При будущей интеграции запуска нужно свежее наблюдение непосредственно перед мутацией: план с окном две минуты не защищает от последующего ручного изменения учётной записи или прав. Непустой Docker, network ownership, data-directory creation, Compose up/readiness, GUI, аппаратная DSM и полные #49/#50/#101 остаются открытыми.

После review проверка содержимого каталога также сохраняет отказ чтения: `find -mindepth 1 -maxdepth 1 -print -quit` возвращает не больше одного полного pathname, код завершения проверяется. Даже имя только из переводов строк не становится пустой строкой благодаря префиксу каталога. Отсутствие/ошибка `find` — Unavailable; список имён не раскрывается. Поддержка опций на DSM остаётся аппаратной проверкой. Публичный `VolumeOf` отклоняет null/некорректный путь безопасным кодом `paths.volume.invalid`.

Протоколы журналов/ownership marker и research/image pins не меняются. Прежние датированные протоколы описывают исторические версии path-протокола; текущее поведение определяют этот ADR и STATUS.
