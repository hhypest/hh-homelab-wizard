# Инструкции для агентов

## Перед работой

Читайте [README](README.md), [STATUS](docs/STATUS.md), [план](docs/DEVELOPMENT_PLAN.md), применимые ADR и инструкции затрагиваемого каталога. Прямые указания владельца в текущем задании приоритетны. Проверьте рабочее дерево, актуальную ветку и изменения владельца; не сбрасывайте их.

Выберите конкретный Issue, прочитайте его критерии, родителя и зависимости по [карте задач](docs/ISSUE_ROADMAP.md). После аудита следуйте [ADR 0008](docs/adr/0008-audit-development-sequence.md) и [реестру находок](docs/audit/2026-10-11-follow-up.md): #97 → #99/#100 → #101. Design/fixtures и одноразовый стенд допустимы до полной M0/M1; это не закрывает приёмку этапов и не разрешает установку NAS.

Текущая готовность хранится только в STATUS, история — в CHANGELOG, доказательства — в протоколах. Не копируйте текущие числа тестов в прозу. Fixture, Docker, CI GUI, обычный клиентский GUI и реальная DSM — разные уровни доказательств.

## Архитектура и качество

- Domain содержит модели и чистые правила; Application — сценарии и порты; Infrastructure — адаптеры; Desktop — Views/VM и composition root. Domain/Application не зависят от Avalonia, SSH/HTTP реализации.
- Модели операций и ErrorCode/Kind определяются в #99. Observe/Apply/Verify разделены; durable intent принадлежит журналу, session auth state — короткоживущей сессии.
- VM на экран, awaitable UI boundary, отмена и защита от второго запуска обязательны. Без .Result/.Wait() в UI и без API/установки в code-behind.
- Pins/API contracts/roles/transforms берутся из версионированного профиля; fixed v1 и optional V2 не смешиваются. Изменение профиля/версии не подхватывается посреди сессии.
- Пишите читаемые методы и условия, один оператор на строку. Форматирование отдельным PR без логических изменений; правила форматтера/анализаторов вводятся в #98. Новые зависимости обоснуйте, закрепите версии и lock-файлы.
- UI тексты и ErrorCode→действие принадлежат Desktop; русский язык UI/документов, английские идентификаторы кода, UTF-8/LF.
- Следуйте общему процессу проверок/PR из [CONTRIBUTING](CONTRIBUTING.md); не дублируйте его здесь.

## Внешние операции и данные

- Перед изменениями нужны свежий снимок и конкретный план ресурсов/путей/портов/зависимостей. Проверки адресов и доступа выполняются из нужного контекста NAS/HA/контейнера, не только с компьютера.
- Применение к реальному NAS допустимо в авторизованном задании; не запрашивайте повторное разрешение на уже согласованные обычные операции. Документация/разработка не разрешает установку.
- Не исполняйте production-операции только для проверки кода; используйте fixtures и изолированные стенды. Не меняйте сеть, firewall, VPN, DHCP, публикацию или облачные привязки ради обхода ошибки.
- Не устанавливайте DSM/Container Manager скрыто; отсутствие prerequisites — понятное действие пользователя.
- Чужой стек блокирует новую установку. Продолжать собственную сессию можно только после проверки ownership, resource/profile identity и состояния.
- Запрещены слепые пересоздания интеграций, правки .storage, удаление баз и compose down -v как средство устранения ошибки.
- Пути проверяйте после разрешения symlink; учитывайте DSM ACL/PUID/PGID/sudo. Без рекурсивного chmod/chown медиатеки. Компенсация конфигурации не удаляет медиатеку и не перезаписывает поздние ручные изменения.
- SSH команды фиксированы; параметры через структурированный payload/stdin/файлы либо строгое POSIX escaping. Без непроверенного UI-ввода в shell и без secrets в process arguments.

## Секреты и неизвестный исход

- Credentials, API/refresh tokens, OTP, webhooks и private keys не попадают в Git, логи, screenshots, exceptions, PR или support bundle. Диагностика содержит безопасные коды, не тела ответа/секретные URL.
- Secrets вводятся локально и живут ограниченное время. До безопасного хранилища Windows/Linux храните в памяти и запрашивайте заново; plaintext journal запрещён.
- SSH host key и TLS проверяются; изменённому ключу не доверять автоматически. Self-signed DSM требует явного trust/pinning, не глобального отключения TLS.
- Атомарный versioned journal фиксирует intent до отправки и confirm после независимого Observe/Verify; ownership/locks и совместимость схемы обязательны.
- Timeout/обрыв/отмена после отправки могут означать выполненную запись. Unknown → Observe, не повтор Apply; отмена не означает откат.
- HTTP 4xx означает доказанный отказ только по подтверждённому контракту версии. Неоднозначный ответ не разрешает повтор.
- Каждая операция описывает компенсацию или невозможность отката; не обещайте транзакцию NAS.

## HA и устройства

- HA — Container без Supervisor/add-on API. Реестры/entries изменяются через проверенные API/flows; .storage можно резервировать, не редактировать для обхода авторизации.
- Сторонние компоненты имеют version/source/hash/licence; не запускайте непроверенный downloaded installer и не переходите на latest.
- DSM сопоставляется по NAS, технической метрике/unique_id, томам/дискам; имена/язык недостаточны. Роли плееров назначаются по integration/device identity, не первому media_player.
- Missing, disabled, unknown, unavailable и ожидание первого измерения различаются. Фиктивные сенсоры/секреты не скрывают отсутствующую интеграцию.
- Перед отключением плеера проверяются YAML/UI/dashboard/dynamic зависимости; неизвестная зависимость запрещает автоматическое отключение.
- Monitor Docker без редактируемого unique_id не получает обещание registry rename. Android TV Remote state не доказывает playback.
- HTTP/reconnect и сопряжение устройств проверяются на закреплённой версии; чужие entries не присваиваются по названию.

## Завершение задания

Используйте отдельную ветку/PR; не сливайте без задания. Синхронизируйте план, Issue/эпик, Milestone и [Project](docs/PROJECT.md) в доступном объёме. Если Project/native API недоступны, сохраните точный статус, родителей и зависимости в Issue и сообщите, что доска/нативные связи не обновлены.

Укажите, что изменено, доказательства и незапущенные проверки. Не объявляйте bootstrap/CI/GUI/DSM успешными без результата и не закрывайте продуктовую задачу от изменения документации. Не отправляйте внешним пользователям сообщения без явного задания.
