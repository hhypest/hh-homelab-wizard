# История изменений

Здесь описываются фактически внесённые изменения hh-homelab-wizard. Версия мастера независима от версии устанавливаемого hh-homelab. Планируемые функции находятся в [плане разработки](docs/DEVELOPMENT_PLAN.md), а не в списке реализованных возможностей.

## Unreleased

### Added

- Общий HTTP exchange сервисных адаптеров, базовый безопасный ContractException и конечная политика ContractHttpTimeouts. Специализированные исключения/коды и HA caller-cancellation/session cleanup сохранены; меньший client timeout действует на получение и обработку ответа. Регрессии бесконечного HttpClient.Timeout, budgets, response disposal и совместимости адаптеров.
- Протокол первичной проверки владельцем сборки e8902bd на Windows и Linux X11/Wayland: все демонстрационные исходы без замечаний; клавиатура, темы, масштабирование и полная матрица остаются открытыми.

- Начальная документация подготовлена 10 октября 2026 года.

- Реестр независимого аудита 11.10.2026 и сведения о его источнике; ADR 0008 с приоритетом транспорта, операций и вертикального сценария qBittorrent на изолированном стенде. Созданы задачи #96–#103 и дополнены критерии существующих Issues; продуктовые ошибки этим не исправлены.
- STATUS как единый источник готовности и шаблон PR с находкой/регрессионным доказательством/ограничениями среды. Project/native связи не обновлены доступным API.

- Публичный GitHub Project «hh-homelab-wizard — Разработка», связанный с репозиторием и Issues десяти Milestones. Пять представлений, семь статусов и правила обновления доски при работе, PR и приёмке. Слияние частичного PR и перемещение карточки не закрывают задачу автоматически; M0/M1 сохраняют открытые критерии.

- GitHub roadmap: Milestones M0–M8 и 2.0.0, эпики с native sub-issues и зависимостями blocked-by, критерии приёмки и метки типа/области/необходимых испытаний. Карта задач связана с планом; доказанные результаты M0/M1 сохранены как закрытые исторические задачи, незавершённые проверки остаются открытыми.

- M1: Application/Desktop, Avalonia 12.1.4 / CommunityToolkit.Mvvm 8.4.2 / DI 10.0.12, compiled bindings и светлая/тёмная тема «Фокус». Четыре демонстрационных экрана и искусственный адаптер без SSH/API/NAS.
- Валидация, ожидание подтверждения, успех, ошибка, неизвестный исход без слепого повтора, остановка и закрытие с ожиданием отмены. Команды и Application защищены от второй одновременной сессии; исключения адаптера не раскрываются в диагностике.
- 15 проверок Application и 8 headless UI-проверок; всего 512 unit/fixture + 8 UI. DesktopProbe отдельно проверяет реальное Win32/X11 окно, сценарии и сохраняет рендеры собственного окна. CI публикует пробные self-contained артефакты Windows/Linux и включает сторонние лицензии.
- ADR 0006 и протокол M1: новая команда владельца завершила паузу после выбора макета. M0/M1 не закрыты; интерактивная клиентская приёмка Windows 11 и Linux остаётся открытой.

- ADR 0005: зафиксирован выбор владельцем макета «Фокус», его компоновка, визуальные ориентиры и состояния будущего интерфейса. README, план M1 и инструкции агентам обновлены; разработка M1 отложена до нового задания, код и зависимости не изменены.

- M0: явный выбор native discovery flows DSM/LG/Android TV/Cast, ограниченный technical DTO, повторная проверка source/unique ID/step и продолжение исходного flow без создания второго. Незавершённый onboarding/existing entry/изменённая identity блокируют сопряжение; Unknown не повторяется.
- Read-only Domain/Infrastructure проверка entry/device/identifier с отдельными Missing/Pending/Disabled/Mismatch/Ambiguous состояниями, DSM root check и нормализацией MAC/Cast UUID. Нативные discovery forms/progress serializer и Cast/Android constructors проверяются на синтетических metadata без регистрации аппаратных entities.
- 51 новая unit/fixture-проверка; всего 497. ADR 0004 отделяет начало демонстрационного M1 от полной приёмки M0; следующим инкрементом планируется Application/Desktop, M0 и M1 не объявлены завершёнными.

- M0: C# USER config flows Synology DSM, LG webOS, Android TV Remote и Google Cast, безопасные состояния credentials/OTP/backup share/confirmation/PIN, entry readback и запрет повторов неизвестного start/submit. DSM TLS проверяется, backup share выбирается явно, Cast hints не считаются выбором GX1.
- Нативная HaDockerProbe проверяет initial forms, LG confirmation form, DSM OTP/backup serializer на синтетической share, loaded Cast и сохранение после restart. Учтены `errors: null` и небезопасный GET DSM OTP в закреплённом HA. Реальное сопряжение, аппаратная identity и общая recovery-сессия остаются открытыми.
- 54 новых unit/fixture-теста шагов, отказов, конфликтов, отмены, потери ответа и запрета повторов; всего 446. Установщик и Avalonia UI ещё не созданы.

- M0: read-only metadata реестров HA, чистый план десяти ролей DSM/LG/GX1/Cast/Jellyfin и enable явно выбранной registry identity. DSM сопоставляется по точным API/metric/unique IDs и связям parent devices; случайный первый плеер не выбирается.
- Enable различает require_restart/reload_delay, проверяет identity/parents/readback и не повторяет update после потерянного ответа. Расширенная HaDockerProbe проверяет source keys DSM, штатный helper, restart и живое состояние после него; реальный DSM/TV этим не подтверждён.
- 49 новых unit/fixture-проверок ролей, конфликтов, parent state, смены identity, enable, потери ответа/отмены и ограниченного DTO; всего 392. Установщик, остальные flows и полный dashboard ещё не реализованы.

- M0: HaRuntimeProbe запускает полный HA-профиль, настоящий Docker Socket Proxy v0.5.0 и безопасный синтетический Docker API через socket собственного volume; host socket и bind mounts не используются. Проверяются метрики, отказы, уведомление, restart, session revocation и cleanup; отдельный Ubuntu job повторяет пробу дважды.
- Read-only наблюдение 40 Docker entities, десяти аппаратных entity IDs и шести scripts с различением Missing/Unknown/Unavailable/Invalid/Available. Сырые attributes и error texts не возвращаются; 29 новых unit/fixture-тестов, всего 343.
- 18 динамических сценариев исходных TV/Resume actions в настоящем Script engine HA 2026.10.0, включая прерывания, ручную защиту, потерю показаний и проверку media ID перед seek. Ускоряются только тестовые копии задержек; фактические устройства и time triggers остаются до аппаратных испытаний.

- M0: проверяемая C#-доставка Monitor Docker из точного commit, raw SHA-256 lock для 39 файлов с лицензией Apache-2.0, ограничения ZIP и отказ при изменении/неполноте/path traversal/symlink. HACS и внешний установочный скрипт не требуются.
- Рендер локального HA-профиля из доверенных fingerprints v1.3.0: Docker/DSM/TV YAML, исключение Alice/Pachca, локальные persistent notifications, явные адреса и секреты в памяти. TAR передаётся потоково, `secrets.yaml` — 0600; TLS-проверка HTTP-датчика включена.
- HaProfileProbe проверяет полный YAML без ошибок/предупреждений, импорты и зависимости Monitor Docker, десять сценариев настоящих HA-шаблонов просмотра в образе 2026.10.0. Добавлены 31 unit/fixture-тест и отдельный Ubuntu runtime job; на этом шаге всего 314 тестов. Объём checker не включает серверный запуск, метрики, устройства, таймеры и полный dashboard.

- M0: первый config flow HA — Jellyfin на закреплённых HA 2026.10.0 / Jellyfin 12.2.0. Явный ввод credentials, безопасные статусы, проверка entry ID, состояния loaded и server ID через device registry; повтор наблюдает результат. Существующие записи не присваиваются по названию, неизвестный результат не вызывает повтор POST. Намерение пока хранится только в памяти; восстановление через журнал M3 не реализовано.
- 19 новых unit/fixture-проверок, всего 283: замечания PR #9, Jellyfin flow, потеря ответа/отмена, конфликт идентичности, pending setup и повтор без записей. HaDockerProbe и Ubuntu CI дополнены отдельным Jellyfin-контейнером, подключением из HA и readback после restart. Это developer tools; M0 остаётся открыт.
- M0: HomeAssistantContractClient для HA Container 2026.10.0 — владелец/onboarding, нормальный login после потерянного ответа, приватные access/refresh tokens, подтверждение owner/admin, HTTP/WebSocket и единичное переименование по идентичности реестра с проверкой коллизий.
- Storage dashboard create/save/readback с явным списком зарегистрированных включённых сущностей; существующая другая конфигурация не перезаписывается. Это тестовая панель, не полный dashboard hh-homelab.

- 53 новых unit/fixture-теста HA, всего 240. Полный профиль, Monitor Docker, реальные config flows/устройства и прикладные автоматизации остаются непроверенными; M0 открыт.

### Changed

- README и правила разработки сокращены, планы различают начало design/fixture работы и полную приёмку; устаревающие текущие числа тестов удалены из статусов. Unreleased приведён к одному разделу каждого типа; исторические доказательства сохранены.

- По решению владельца Windows 10 исключена из поддерживаемых платформ и приёмки. Остаются Windows 11 x64 и Linux x64 / X11 и Wayland, базовый дистрибутив Ubuntu 24.04 LTS. ADR 0007 и текущие требования обновлены в том же PR M1.
- Добавлен Avalonia.Wayland 12.1.4 и общий startup приложения/пробы: нативный Wayland при заданном WAYLAND_DISPLAY, fallback на X11 при недоступном compositor. CI отдельно проверяет X11, fallback и Wayland без DISPLAY; probe проверяет реальный backend и учитывает отсутствие публичного native handle у Wayland.

- Дополнен план будущей версии 2.0.0: выбор компонентов и функций, опциональные Sonarr/Radarr/Bazarr и Home Assistant, выбор FlareSolverr/Byparr/Solvearr/NoFlare либо режима «Не использовать», генерация конфигурации по зависимостям, перенос профилей и документации в wizard и условия архивирования hh-homelab. Добавлены этапы V2.1–V2.6, источники обработчиков и критерии приёмки; это изменение документации, функции ещё не реализованы и архивирование не выполнялось.
- Уточнена обязательная клиентская матрица первого выпуска: Windows 11 x64 и Ubuntu 24.04 LTS x64 / X11 и Wayland. Требования к приёмке и испытаниям обновлены; совместимость приложения пока не проверена.

### Fixed

- B1/B2, первый инкремент #97: deadline/IO чтения qBittorrent/Arr/Jellyfin/Seerr нормализованы в безопасные ошибки Transport; отмена/потеря ответа после начала записи даёт Unknown без автоматического повтора. Добавлены typed Kind, регрессии ожидания/тела ответа и form login Arr; qBittorrent preflight/login/version/preferences/categories не выпускают raw сетевые исключения. Объединение транспорта и общие политики остаются открытыми.

- По замечаниям Codex к PR #104: протокол M1 различает ранние инкременты M2 и полную приёмку; ID аудита и обновление документов в PR требуются только при применимости. Вместо полной копии внешнего отчёта с неизвестной лицензией сохранены происхождение и SHA-256.
- CI: повторяется только скачивание образа при transient registry/network ошибке, максимум четыре попытки с ожиданием 15/30/60 секунд. Ошибки доступа, неверный pin и неизвестные отказы завершаются сразу; версии образов и установочные операции не меняются. Политика проверяется изолированными shell-тестами в Linux CI.

- По замечанию Codex P2 к PR #12: после `docker start` proxy проверяется с ограниченным ожиданием GET readiness. Временный отказ соединения больше не обрывает recovery; проба начинает ожидание до запуска остановленного proxy. POST policy проверяется однократно после готовности.
- По замечаниям Codex к PR #9: deadline ожидания RUNNING выдаёт `ha.startup.timeout`; окончательный отказ HTTP configure очищает намерение и запрещает присвоить позднейший чужой trial. `DisposeAsync` сохраняет диагностический код cleanup, не подменяя исходную ошибку при выходе из `await using`; обязательный отзыв проверяется явным `RevokeSessionAsync` и `SessionRevocationConfirmed`.
- Пробы Jellyfin ждут основной API через `Startup/User`: ранний 200 временного SetupServer на `System/Info/Public` больше не принимается за готовность. Адаптер явно запрашивает JSON-профиль PascalCase; выбор формата не зависит от default transport/server.
- По замечаниям Codex к PR #7: HA-клиент не принимает и не подтверждает pending HTTP trial без собственного намерения configure, даже при полном совпадении значений. Новый клиент блокирует такой trial; перенос подтверждённого намерения между запусками остаётся задачей журнала M3.
- HomeAssistantContractClient использует `IAsyncDisposable`: собственный refresh token отзывается через `/auth/revoke` перед новой авторизацией, при ошибке проверки владельца/конфигурации и штатном завершении. Неудачный отзыв сохраняет приватный токен для явного повторного cleanup и сообщает безопасный код; чужие сессии не удаляются.
- Внутренний таймаут HA WebSocket/HTTP больше не выдаётся за отмену пользователем: результат записи обозначается неизвестным, чтение — ошибкой транспорта. Явная отмена сохраняет `OperationCanceledException`; записи не повторяются автоматически.
- Добавлены 24 регрессионные проверки; всего 264 unit/fixture-теста. HaDockerProbe дополнен отказом другого клиента от идентичного trial, проверкой отсутствия лишних токенов через API metadata и потерей ответа отзыва с явным повтором cleanup.
- По замечаниям Codex к PR #2: валидатор больше не принимает плавающие теги с цифрами (`latest2`, `stable2026`) у образов и Docker mods; допускаются явные форматы версий и упаковки исходного профиля.
- Проверка credentials qBittorrent требует отказа доступа до login и останавливается при уже открытой сессии или обходе авторизации; защищённые GET отправляют Referer.
- Диагностика QbProbe различает login 401, 403 и остальные HTTP-ошибки, сохраняет числовой статус и не выводит credentials или response body.
- Добавлены регрессионные проверки этих случаев; на этом шаге набор содержал 63 unit/fixture-теста.

После первого выпуска добавляйте разделы версий с датой, изменениями поведения и значимыми ограничениями. Не переносите будущие этапы в `Added` до их реализации.
