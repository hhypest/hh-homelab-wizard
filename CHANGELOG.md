# История изменений

Здесь описываются фактически внесённые изменения hh-homelab-wizard. Версия мастера независима от версии устанавливаемого hh-homelab. Планируемые функции находятся в [плане разработки](docs/DEVELOPMENT_PLAN.md), а не в списке реализованных возможностей.

## Unreleased

### Added

- Каталоги монтирования qBittorrent в исполняемом графе #101/#53: после маркера граф создаёт `media/config/qbittorrent` и `media/watch` с режимом 750 операциями `ConfigurationDirectory`, параллельно Compose и .env. Каталог, заранее созданный Docker от root или с другим режимом, — Conflict без изменений; потеря ответа — Unknown с подтверждением наблюдением новым процессом. Сеть и запуск контейнера ещё не реализованы. [ADR 0023](docs/adr/0023-qbittorrent-configuration-graph.md), [протокол](docs/testing/2026-10-19-qbittorrent-configuration-graph.md#каталоги-монтирования-в-графе).

- Создание конфигурационных каталогов #53/#101: операция `ConfigurationDirectory` создаёт каталог (с недостающими родителями) под собственным маркером через общий сценарий и журнал. Каталог сразу получает режим 700/750/755 (`mkdir -m`). Существующий каталог принимается только как каталог пользователя SSH с теми же правами (унаследованный setgid общей папки допустим) и никогда не меняется: ни chmod, ни chown, ни очистки. Каталог, созданный Docker от root, — Conflict. Путь проходится через `cd -P` со сверкой `pwd -P`; потеря ответа — Unknown с подтверждением наблюдением. [ADR 0024](docs/adr/0024-configuration-directories.md), [протокол](docs/testing/2026-10-19-configuration-directories.md).
- Семантика «отправлено» для SSH-операций записи: запрос считается возможно доставленным с начала записи stdin, потому что скрипт действует по последней строке запроса. `NotSent` — только сбой подключения, аутентификации или запуска команды (ADR 0018/0022).

- Compose и .env qBittorrent из конкретного плана #101/#50: сервис повторяет закреплённый источник (образ, mods, монтирования, публикации, сеть, журналы) с выровненным WebUI port; `.env` содержит только выбранные значения. Свежий план без Blocking превращается в исполняемый граф (маркер → Compose и .env) со стабильными ID для возобновления; единый порт владения маршрутизирует проверки по ресурсам. Каталоги монтирования, сеть и запуск контейнера ещё не реализованы. [ADR 0023](docs/adr/0023-qbittorrent-configuration-graph.md), [протокол](docs/testing/2026-10-19-qbittorrent-configuration-graph.md).

- Первый инкремент доставки #53: операция `ConfigurationFile` сервиса `nas` создаёт один файл по относительному пути (ASCII, до 8 компонентов, режим 600/640/644, до 64 KiB) под собственным маркером через общий сценарий и журнал. Фиксированный read-only скрипт сверяет маркер и сообщает размер, режим и SHA-256 без содержимого; скрипт записи принимает сырые байты через stdin в приватное имя внутри каталога маркера, сверяет размер и хеш, затем создаёт родительские каталоги и публикует файл без замены. Существующий другой файл, в том числе изменённый вручную после создания, — Conflict без перезаписи; потеря ответа — Unknown с подтверждением наблюдением. Скрипты закрепляют каталоги и открытый файл (`cd -P`/`pwd -P`, `/proc/self/fd`), повторно проверяют маркер перед первым изменением и после публикации, публикуют через `ln -T` и не принимают имена, начинающиеся с `-`. Замена, backup и компенсация не реализованы. [ADR 0022](docs/adr/0022-configuration-file-delivery.md), [протокол](docs/testing/2026-10-19-configuration-file-delivery.md).

- Первый конкретный read-only план qBittorrent #50: явные пути/порты/PUID/PGID/бюджеты, versioned template с provenance и общими image pins; неизменяемые ресурсы, ownership, публикации TCP/UDP и три контекста адресов. Compiler заново собирает связанные host/path snapshots; перепроверка обнаруживает drift и падение свободного места ниже бюджета. Неисполненные проверки остаются видимыми; UI, delivery и полный стек ещё не подключены. [ADR 0021](docs/adr/0021-qbittorrent-installation-plan.md), [протокол](docs/testing/2026-10-19-qbittorrent-plan.md).

- Исполнитель конфигурационного графа #52 поверх прежнего Observe/Apply/Verify: неизменяемые зависимости и бюджеты, обязательная атомарная привязка полного плана к локальному журналу schema 2, остановка при любом неуспехе и отчёт уже начатых шагов. Resume заново проверяет каждый ресурс; другой граф/параметры/identity/бюджет блокируются. Process-restart проба расширена принудительным завершением во время Apply, восстановлением без второго изменения и отказом изменённому графу. Schema 1 отклоняется без сброса/миграции; полноценная #52, Desktop, SSH/Compose-вертикаль и DSM остаются открытыми.

- Удалённая блокировка установки #51: каталог `lock` с session GUID внутри собственного маркера, атомарный `mkdir`, повторный захват той же сессией, отчёт о чужой (GUID и возраст) без автоматического перехвата, освобождение только своей. `RemoteLockedOperationJournal` держит её поверх локального lease на всю операцию; занятая блокировка останавливает сценарий до первого шага. Потеря ответа — Unknown. Стенд проверяет две сессии, сценарий под блокировкой и потерю ответа. [ADR 0019](docs/adr/0019-remote-installation-lock.md), [протокол](docs/testing/2026-10-19-remote-lock.md).

- Создание маркера владения #51/#53 — первая журналируемая мутация NAS: операция `OwnershipMarker` сервиса `nas` идёт через общий сценарий (Observe → intent → Apply → Verify → confirm) и локальный журнал. Фиксированный скрипт получает корень и маркер через stdin, проверяет symlink, права и пустоту до первого изменения и публикует маркер без замены (`ln`). Доказанный отказ — Rejected, потеря ответа после отправки — Unknown, новый процесс подтверждает наблюдением без второй записи; остаток прерванного создания наблюдается как `staged`. Стенд проверяет запись, resume после потери ответа, отказы и чужие корни. [ADR 0018](docs/adr/0018-ownership-marker-creation.md), [протокол](docs/testing/2026-10-19-ownership-marker-creation.md).

- Read-only маркер владения #51: `.hh-homelab-wizard/installation.json` в корне конфигурации со схемой, installation ID и профилем читается в том же SSH-вызове проверки путей (hex, строгий JSON). Оценка различает новую, свою и чужую установку, смену профиля, содержимое без маркера и недействительный/symlink/недоступный маркер; без ожидаемого владельца маркер не присваивается. Коды `paths.configuration-root.*` заменены на `ownership.*`. Создание маркера и remote lock не реализованы. [ADR 0017](docs/adr/0017-installation-ownership-marker.md), [протокол](docs/testing/2026-10-19-ownership-marker.md).

- Read-only проверка путей #49: `MediaPathLayout` из корня данных и корня конфигурации ниже `/volumeN` с фиксированными `torrents`/`media` подкаталогами, пути только через stdin фиксированного скрипта. Symlink в пути или предке, файл вместо каталога, недоступный путь и отсутствующий том блокируют затронутую роль; существующая медиатека разрешена, непустая конфигурация требует ownership, загрузки и медиатека должны быть на одном устройстве. Permissions Unverified, DSM ACL NotChecked. Стенд проверяет синтетическое дерево и литеральность путей с shell-метасимволами. [ADR 0016](docs/adr/0016-remote-path-inspection.md), [протокол](docs/testing/2026-10-19-remote-paths.md).

- Preflight #48, протокол v2: модель NAS из кандидатного `synoinfo.conf`, TCP-слушатели из `/proc/net/tcp(6)` и общий/свободный объём только `/volumeN`. `PreflightRequirements` плана сверяет порты и место: конфликт, отсутствующий том, нехватка места и нечитаемые данные блокируют; без требований проверки остаются NotChecked. Лимиты укладываются в 16 KiB, свободное место не меняет environment fingerprint. Стенд проверяет настоящий слушатель sshd и отсутствие DSM-томов. [ADR 0015](docs/adr/0015-preflight-host-resources.md), [протокол](docs/testing/2026-10-19-preflight-resources.md).

- Стендовый Docker/Compose-инкремент #48: отдельный GitHub-hosted-only режим с настоящим вложенным daemon, проверкой password/key, empty/nonempty inventory, resource drift, socket/plugin denial, environment overrides и daemon restart/recovery. Production collector не меняется; logical resource state сравнивается до/после. CI разделяет обычный unprivileged SSH fixture и privileged dind только внутри одноразовой VM; без host socket/bind mounts. [ADR 0014](docs/adr/0014-docker-preflight-runtime.md) и [протокол](docs/testing/2026-10-19-docker-preflight.md) фиксируют границы и доказательства.

- Первый preflight-инкремент #48: Domain facts/snapshot/assessment и Application порт, SSH-сбор фиксированных read-only сведений об OS/architecture/time, кандидатных DSM/Container Manager версиях, Docker server/Compose и bounded container IDs. Snapshot привязан к SSH principal/host key/profile/локальному интервалу; свежесть и environment drift проверяются отдельно от readiness. Неполные/повреждённые ответы не дают частичного success; версии остаются Unverified, недостающие проверки — NotChecked. Добавлены fixtures и preflight-сценарии в одноразовом OpenSSH-стенде; hardware и положительные Docker-through-SSH branches остаются открытыми.

- Одноразовый OpenSSH/SFTP Docker-стенд #46: синтетический пароль и зашифрованный приватный ключ, независимая сверка публичного host key, первый trust/смена ключа, неверные credentials, повреждённый/избыточный ответ, недоступный SFTP, sudo-list denial, Busy, отмена, timeout, обрыв и повторное подключение. Новая SSH runtime job запускает сценарии дважды на свежих контейнерах; база закреплена digest, прямые пакеты — версиями. Доказательства и ограничения — в [протоколе](docs/testing/2026-10-19-ssh-runtime.md).

- Первый SSH-инкремент #46: Domain typed read-only evidence, Application порт и Infrastructure на закреплённой SSH.NET 2026.0.0. Явный host/port-bound SHA-256 pin до авторизации, отдельная проверка SFTP, memory-only password/private key/passphrase, фиксированные команды чтения и stat, конечный budget/cancel, bounded output и защита от второго запуска; fixtures и локальные TCP timeout/cancel тесты. Живой SSH/SFTP/DSM smoke остаётся открытым. Владелец полностью принял клиентскую матрицу PR #110 на Windows 11 26H1 / Ubuntu 24.04.4 LTS GNOME X11 и Wayland; #42–#45 выполнены.

- Первый файловый инкремент #51: явные Create/Open, versioned session/profile journal с hash и bounded validation, atomic intent/confirm и локальная межпроцессная lease. JournalProbe проверяет принудительное завершение процесса и продолжение без повторного Apply; включён в Windows/Linux core CI. Remote lock/ownership и power-loss durability остаются открытыми. Протокол M1 дополнен полной проверкой клавиатуры/тем/масштабирования владельцем на 1a42f4b, Windows 11 26H1 и Ubuntu 24.04.4 LTS GNOME X11/Wayland.

- Модели identity/resource/observation/verification и типизированные исходы операций; однооперационный Application Observe/Apply/Verify с обязательными journal lease/ownership портами. Pending intent запрещает слепой Apply; независимая проверка предшествует confirm. Образцы qB category и Radarr root за портами, привязка фактического API endpoint, безопасный Desktop code/kind presenter. Долговечный журнал, NAS/SSH и экранное подключение остаются отдельными задачами.

- Первый инкремент #100: схема 2 research profile с ожидаемыми версиями API, неизменяемый PinnedRuntimeProfile для клиентов/проб, проверка совместимости полного внешнего профиля и выбор образов CI через ProfileCheck. Pins/source hashes сохранены; схема 1 читается только как прежний каталог. Monitor Docker сверяет metadata с профилем и lock; роли/transforms/paths остаются отдельной работой.
- Общий HTTP exchange сервисных адаптеров, базовый безопасный ContractException и конечная политика ContractHttpTimeouts. Специализированные исключения/коды и HA caller-cancellation/session cleanup сохранены; меньший client timeout действует на получение и обработку ответа. Регрессии бесконечного HttpClient.Timeout, budgets, response disposal и совместимости адаптеров.
- Протокол первичной проверки владельцем сборки e8902bd на Windows и Linux X11/Wayland: все демонстрационные исходы без замечаний; клавиатура, темы, масштабирование и полная матрица остаются открытыми.

Объединение транспорта и общие политики остаются открытыми.

- По замечаниям Codex к PR #104: протокол M1 различает ранние инкременты M2 и полную приёмку; ID аудита и обновление документов в PR требуются только при применимости. Вместо полной копии внешнего отчёта с неизвестной лицензией сохранены происхождение и SHA-256.
- CI: повторяется только скачивание образа при transient registry/network ошибке, максимум четыре попытки с ожиданием 15/30/60 секунд. Ошибки доступа, неверный pin и неизвестные отказы завершаются сразу; версии образов и установочные операции не меняются. Политика проверяется изолированными shell-тестами в Linux CI.

- По замечанию Codex P2 к PR #12: после `docker start` proxy проверяется с ограниченным ожиданием GET readiness. Временный отказ соединения больше не обрывает recovery; проба начинает ожидание до запуска остановленного proxy. POST policy проверяется однократно после готовности.
- По замечаниям Codex к PR #9: deadline ожидания RUNNING выдаёт `ha.startup.timeout`; окончательный отказ HTTP configure очищает намерение и запрещает присвоить позднейший чужой trial. `DisposeAsync` сохраняет диагностический код cleanup, не подменяя исходную ошибку при выходе из `await using`; обязательный отзыв проверяется явным `RevokeSessionAsync` и `SessionRevocationConfirmed`.
- Пробы Jellyfin ждут основной API через `Startup/User`: ранний 200 временного SetupServer на `System/Info/Public` больше не принимается за готовность. Адаптер явно запрашивает JSON-профиль PascalCase; выбор формата не зависит от default transport/server.
- По замечаниям Codex к PR #7: HA-клиент не принимает и не подтверждает pending HTTP trial без собственного намерения configure, даже при полном совпадении значений. Новый клиент блокирует такой trial; перенос подтверждённого намерения между запусками остаётся задачей журнала M3.
- HomeAssistantContractClient использует `IAsyncDisposable`: собственный refresh token отзывается через `/auth/revoke` перед новой авторизацией, при ошибке проверки владельца/конфигурации и штатном завершении. Неудачный отзыв сохраняет приватный токен для явного повторного cleanup и сообщает безопасный код; чужие сессии не удаляются.
- Внутренний таймаут HA WebSocket/HTTP больше не выдаётся за отмену пользователем: результат записи обозначается неизвестным, чтение — ошибкой транспорта. Явная отмена сохраняет `OperationCanceledException`; записи не повторяются автоматически.
- Добавлены 24 регрессионные проверки; всего 264 unit/fixture-теста. HaDockerProbe дополнен отказом другого клиента от идентичного trial, проверкой отсутствия лишних токенов через API metadata и потерей ответа отзыва с явным повтором cleanup.
