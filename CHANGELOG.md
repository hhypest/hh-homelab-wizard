# История изменений

Здесь описываются фактически внесённые изменения hh-homelab-wizard. Версия мастера независима от версии устанавливаемого hh-homelab. Планируемые функции находятся в [плане разработки](docs/DEVELOPMENT_PLAN.md), а не в списке реализованных возможностей.

## Unreleased

### Added

- M0: проверяемая C#-доставка Monitor Docker из точного commit, raw SHA-256 lock для 39 файлов с лицензией Apache-2.0, ограничения ZIP и отказ при изменении/неполноте/path traversal/symlink. HACS и внешний установочный скрипт не требуются.
- Рендер локального HA-профиля из доверенных fingerprints v1.3.0: Docker/DSM/TV YAML, исключение Alice/Pachca, локальные persistent notifications, явные адреса и секреты в памяти. TAR передаётся потоково, `secrets.yaml` — 0600; TLS-проверка HTTP-датчика включена.
- HaProfileProbe проверяет полный YAML без ошибок/предупреждений, импорты и зависимости Monitor Docker, десять сценариев настоящих HA-шаблонов просмотра в образе 2026.10.0. Добавлены 31 unit/fixture-тест и отдельный Ubuntu runtime job; всего 314 тестов. Серверный запуск полного профиля, реальные метрики/устройства, таймеры и полный dashboard ещё не подтверждены.

### Fixed

- По замечаниям Codex к PR #9: deadline ожидания RUNNING выдаёт `ha.startup.timeout`; окончательный отказ HTTP configure очищает намерение и запрещает присвоить позднейший чужой trial. `DisposeAsync` сохраняет диагностический код cleanup, не подменяя исходную ошибку при выходе из `await using`; обязательный отзыв проверяется явным `RevokeSessionAsync` и `SessionRevocationConfirmed`.
- Пробы Jellyfin ждут основной API через `Startup/User`: ранний 200 временного SetupServer на `System/Info/Public` больше не принимается за готовность. Адаптер явно запрашивает JSON-профиль PascalCase; выбор формата не зависит от default transport/server.
- По замечаниям Codex к PR #7: HA-клиент не принимает и не подтверждает pending HTTP trial без собственного намерения configure, даже при полном совпадении значений. Новый клиент блокирует такой trial; перенос подтверждённого намерения между запусками остаётся задачей журнала M3.
- HomeAssistantContractClient использует `IAsyncDisposable`: собственный refresh token отзывается через `/auth/revoke` перед новой авторизацией, при ошибке проверки владельца/конфигурации и штатном завершении. Неудачный отзыв сохраняет приватный токен для явного повторного cleanup и сообщает безопасный код; чужие сессии не удаляются.
- Внутренний таймаут HA WebSocket/HTTP больше не выдаётся за отмену пользователем: результат записи обозначается неизвестным, чтение — ошибкой транспорта. Явная отмена сохраняет `OperationCanceledException`; записи не повторяются автоматически.
- Добавлены 24 регрессионные проверки; всего 264 unit/fixture-теста. HaDockerProbe дополнен отказом другого клиента от идентичного trial, проверкой отсутствия лишних токенов через API metadata и потерей ответа отзыва с явным повтором cleanup.
- По замечаниям Codex к PR #2: валидатор больше не принимает плавающие теги с цифрами (`latest2`, `stable2026`) у образов и Docker mods; допускаются явные форматы версий и упаковки исходного профиля.
- Проверка credentials qBittorrent требует отказа доступа до login и останавливается при уже открытой сессии или обходе авторизации; защищённые GET отправляют Referer.
- Диагностика QbProbe различает login 401, 403 и остальные HTTP-ошибки, сохраняет числовой статус и не выводит credentials или response body.
- Добавлены регрессионные проверки этих случаев; на этом шаге набор содержал 63 unit/fixture-теста.

### Added

- M0: первый config flow HA — Jellyfin на закреплённых HA 2026.10.0 / Jellyfin 12.2.0. Явный ввод credentials, безопасные статусы, проверка entry ID, состояния loaded и server ID через device registry; повтор наблюдает результат. Существующие записи не присваиваются по названию, неизвестный результат не вызывает повтор POST. Намерение пока хранится только в памяти; восстановление через журнал M3 не реализовано.
- 19 новых unit/fixture-проверок, всего 283: замечания PR #9, Jellyfin flow, потеря ответа/отмена, конфликт идентичности, pending setup и повтор без записей. HaDockerProbe и Ubuntu CI дополнены отдельным Jellyfin-контейнером, подключением из HA и readback после restart. Это developer tools; M0 остаётся открыт.
- M0: HomeAssistantContractClient для HA Container 2026.10.0 — владелец/onboarding, нормальный login после потерянного ответа, приватные access/refresh tokens, подтверждение owner/admin, HTTP/WebSocket и единичное переименование по идентичности реестра с проверкой коллизий.
- Storage dashboard create/save/readback с явным списком зарегистрированных включённых сущностей; существующая другая конфигурация не перезаписывается. Это тестовая панель, не полный dashboard hh-homelab.
- HTTP protection: наблюдение RUNNING, pending/restart/reconnect, проверка active trial и явное promote; failed/reverted/foreign pending блокирует подтверждение. Настройки IP ban/threshold=5 и отсутствие trusted proxies подтверждаются после перезапуска.
- HaDockerProbe на собственном свежем контейнере и config volume, без host mounts/socket, устройств и редактирования .storage. Шесть потерянных ответов, отказ неверного пароля, повтор без конфигурационных записей и сохранение после restart; отдельный Ubuntu job выполняет два свежих сценария.
- 53 новых unit/fixture-теста HA, всего 240. Полный профиль, Monitor Docker, реальные config flows/устройства и прикладные автоматизации остаются непроверенными; M0 открыт.
- M0: C#-контракты Jellyfin 12.2.0 и Seerr 3.5.0: первый администратор, локаль ru/RU, две библиотеки, владелец Seerr через Jellyfin, включение конкретных library IDs и default-связи с Radarr/Sonarr. API Test проверяет выбранные существующие quality profiles и root folders до/после сохранения; initialize требует повторного подтверждения библиотек и связей.
- MediaDockerProbe: четыре собственных временных контейнера, read-only mount медиатеки Jellyfin, пять потерянных успешных ответов с последующим наблюдением, отказ неверных паролей, повтор и сохранение после restart без конфигурационных записей. Используется современный Authorization MediaBrowser Token Jellyfin; legacy-авторизация не включается.
- 48 новых unit/fixture-проверок Jellyfin/Seerr; на этом шаге набор содержал 187 тестов. Отдельное Ubuntu CI-задание повторяет Media probe дважды на свежих конфигурациях. Установщик, журнал и Avalonia UI ещё не реализованы; пользовательские политики Jellyfin и воспроизведение не проверены этим инкрементом.
- M0: C#-контракты Radarr 6.4.4.10685, Sonarr 4.0.20.3014 и Prowlarr 2.6.5.5623 для Forms/enabled, root folders, download clients qBittorrent и applications с fullSync. Проверяются версия, состояние и соединение; маскированные секреты проверяются через API Test.
- ArrDockerProbe и общий ProbeSupport: только собственные локальные Docker resources, синтетические доступы в памяти, повтор без create/update, наблюдение после потери ответа, отказ при конфликте и проверка сохранения после stop/start с повторным чтением host ports.
- 47 новых unit/fixture-проверок Arr; на этом шаге набор содержал 139 тестов. Ubuntu CI повторяет Arr bootstrap дважды на свежих конфигурациях.

- Следующий шаг M0: конфигурационные API-контракты qBittorrent 5.2.4 для download settings, смены credentials и категорий с проверкой результата, конфликтов и неизвестного исхода записи.
- C# QbDockerProbe: локальные disposable Docker resources, временный пароль только в памяти, повтор без дублей, искусственная потеря ответа создания категории, проверка старых/новых credentials и сохранения после stop/start, cleanup с проверкой владения.
- Отдельное CI-задание Ubuntu для двух запусков bootstrap на свежих контейнерах. 29 новых unit/fixture-тестов; на этом шаге набор содержал 92 проверки.

### Project status

- Начальная документация подготовлена 10 октября 2026 года.
- Ядро и developer tools собираются; M0 не закрыт. Автоматического установщика, Avalonia UI и пользовательских пакетов пока нет.
- Локальная сборка, unit/fixture-тесты и часть disposable Docker-проб выполнены. Bootstrap/configuration qBittorrent и Arr подтверждены в объёме протокола; остальные пункты M0 остаются открытыми. UI-тесты и установка на NAS не выполнялись.

### Changed

- Дополнен план будущей версии 2.0.0: выбор компонентов и функций, опциональные Sonarr/Radarr/Bazarr и Home Assistant, выбор FlareSolverr/Byparr/Solvearr/NoFlare либо режима «Не использовать», генерация конфигурации по зависимостям, перенос профилей и документации в wizard и условия архивирования hh-homelab. Добавлены этапы V2.1–V2.6, источники обработчиков и критерии приёмки; это изменение документации, функции ещё не реализованы и архивирование не выполнялось.
- Уточнена обязательная клиентская матрица первого выпуска: Windows 10 x64, Windows 11 x64 и Ubuntu 24.04 LTS x64 / X11. Требования к приёмке и испытаниям обновлены; совместимость приложения пока не проверена.

После первого выпуска добавляйте разделы версий с датой, изменениями поведения и значимыми ограничениями. Не переносите будущие этапы в `Added` до их реализации.
